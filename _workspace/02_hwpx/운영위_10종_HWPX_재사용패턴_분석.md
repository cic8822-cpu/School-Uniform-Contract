## 2. 재사용 가능한 설계 패턴

1. **단일 회차 컨텍스트 + 문서별 독립 생성**: 하나의 회차/기관 컨텍스트를 여러 절차 문서에 적용하되, 결과는 문서 역할별 독립 HWPX로 보관함.
2. **번호·파생문서 명명**: 기본 서식 번호에 `-1`, `-2`를 붙여 같은 단계의 파생 산출물을 구분함. 문서명에는 서식 식별자, 업무 유형, 회차 식별자를 결합함.
3. **절차 종속 출력 묶음**: 상류 문서에서 확정한 회차·일정·상태 등 공통값이 공고·안내·출석·결과·회의록 성격의 문서군으로 이어지는 구조로 보임. 단, 소스 코드·실행 로그·입력 원본이 없어 실제 자동 전파 메커니즘까지는 증명하지 못함.
4. **독립 파일 사본 우선**: 파일군은 복합 매뉴얼 한 파일이 아니라 문서 1종당 HWPX 1개로 분리되어 있음. 따라서 치환 대상 범위를 Form ID 단위로 물리적으로 제한할 수 있음.

## 3. 교복구매 P2-01에 대한 권고

- 현재 P2-01의 핵심 위험인 복합 매뉴얼 전역 치환을 피하기 위해, 우선 Form ID별 독립 템플릿 사본을 승인·추적 가능한 경로에 둠.
- 독립 사본이라고 해서 Kordoc `fill` 성공이 자동 보장되지는 않음. 본 분석 파일군에도 `hp:fieldBegin`/`hp:bookmark`가 없으므로, 실제 생성 도구가 텍스트·표 셀을 직접 갱신했을 가능성이 있음. 교복구매는 사본에서 Form ID·위치 ID가 포함된 고유 토큰을 삽입한 뒤 Kordoc `fill -j` 성공을 별도 입증해야 함.
- 출력 단위는 `Form ID/회차 식별자`를 포함한 파일명으로 고정하고, 생성본·검증 PDF·마스킹 로그를 Form ID별 하위 폴더에 함께 보관함.
- 개인식별·연락처·서명·원문 안건은 템플릿 토큰, 테스트 JSON, 검증 로그, 파일명에 포함하지 않음. 해당 항목은 빈칸 유지 또는 수동 후처리로 경계를 유지함.
