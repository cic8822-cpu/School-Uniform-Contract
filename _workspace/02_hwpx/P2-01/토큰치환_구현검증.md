# P2-01 HWPX 명시적 토큰 치환 구현·검증

- 상태: `구현 및 자동 검증 완료(한컴 수동 열기·PDF 비교는 P2-02에서 별도 수행)`
- 대상: F-007 생성 사본 `artifacts/hwpx/P2-01/F007_구매요청_템플릿.hwpx`
- 원본 보호: `교복4차 (2)/` 아래의 원본 HWPX는 읽기 전용이며 이 절차는 수정하지 않는다.

## CLI 계약

```powershell
powershell -ExecutionPolicy Bypass -File scripts/hwpx_token_fill.ps1 `
  -TemplatePath <토큰이_삽입된_사본.hwpx> `
  -JsonPath <UTF-8_BOM_없는_공통값.json> `
  -OutputPath artifacts/hwpx/<FormID>_생성본.hwpx
```

JSON 최상위 키는 아래 공통·비식별 항목만 허용한다. 값은 문자열이고 JSON은 반드시 UTF-8 BOM 없이 저장한다.

```json
{"학교명":"검증초등학교","학년도":"2026학년도","문서번호":"검증초-2026-1","발행일":"2026. 3. 2."}
```

허용 키: `학교명`, `학년도`, `문서번호`, `발행일`, `제목`, `수신기관`, `시행일`, `공개구분`.

`성명`, `교장명`, `담당자`, 연락처, 주소, 이메일, 서명, 직인, 계좌, 주민번호, 설문 관련 토큰은 스크립트가 명시적으로 거부한다. F-029/F-047/F-050 및 개인식별 데이터는 이 경로에 넣지 않는다.

## 구현 방식과 한계

- `Contents/section*.xml`의 `<hp:t>`만 원문 바이트 텍스트 형태로 바꾸며, XML 전체 재직렬화·문단/런/스타일 ID 변경을 하지 않는다.
- `{{학교명}}`처럼 하나의 토큰이 인접한 여러 `<hp:t>` 런으로 분절되어도 같은 문단에서 조합해 찾고, 첫 런에 값·나머지 런에는 빈 문자열을 넣어 원래 런 구조와 스타일 참조를 보존한다.
- 토큰은 문단을 넘을 수 없고, 토큰 텍스트 안에 XML 엔터티를 넣지 않는 것을 템플릿 작성 규칙으로 한다.
- 출력 파일은 입력 사본과 반드시 다른 경로여야 한다. Excel VBA 직접 호출은 아직 연결하지 않았고, 이후 연계 시에도 이 JSON/파일 계약과 종료 코드를 따른다.

## 자동 검증

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify_hwpx_token_fill.ps1
```

검증기는 F-007 사본을 `_workspace/02_hwpx/P2-01/토큰치환_검증산출/`에 복사한 뒤 공통 토큰 네 개를 삽입하고 `{{학교명}}`을 두 XML 런으로 의도적으로 분절한다. 그 뒤 BOM 없는 JSON으로 채워 다음을 검사한다.

1. 기준 사본 SHA-256 불변, ZIP 엔트리 목록 보존
2. 모든 XML 파싱 가능, 미치환 `{{…}}` 0개, 네 값 모두 존재
3. Kordoc `validate` 및 `render` 성공, SVG 생성

검증기는 고정된 `kordoc@4.13.1`을 사용한다. 이는 구조·재열기·렌더 가능성 자동 확인이다. 한컴 COM으로 실제 열기/저장, 한컴 PDF 내보내기 및 페이지 조판 비교는 이 스크립트가 자동화하지 않는다. 설치된 한컴 환경에서 생성본을 직접 열고 PDF로 내보낸 뒤 원본과 페이지 수·줄바꿈·표 분할을 비교하는 P2-02 수동 게이트가 필수다.

출력 파일은 같은 디렉터리의 GUID 임시 파일에서 ZIP/XML/토큰 검증을 모두 통과한 뒤에만 원자적으로 교체한다. 실패 시 기존 출력본은 유지된다.

## Excel 기초자료 CLI 연계

```powershell
powershell -ExecutionPolicy Bypass -File scripts/export_hwpx_from_excel.ps1 `
  -ExcelPath artifacts/excel/교복구매_길라잡이_YYYYMMDD_vN.xlsm `
  -TokenTemplatePath _workspace/02_hwpx/P2-01/토큰치환_검증산출/F007_명시적토큰_템플릿.hwpx `
  -OutputPath artifacts/hwpx/P2-01/F007_생성본.hwpx
```

이 CLI는 Excel을 VBA 비실행(`AutomationSecurity=3`)·읽기 전용으로 열고 `기초자료입력`의 C4/C5/C8/C9와 F-007 문서별 C21/C22만 읽는다. 추출 JSON은 작업 폴더 GUID 임시 파일이며 `finally`에서 삭제한다. 교장명·성명·서명·연락처는 읽기/JSON/출력 경로에 존재하지 않는다. 생성 뒤 ZIP/XML·토큰 0·`kordoc@4.13.1 validate/render`·입력 XLSM/HWPX SHA-256 불변을 확인한다. Excel VBA 버튼 통합은 하지 않는다.

회귀 검증 명령:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify_excel_hwpx_export.ps1
```

2026-09-19에는 Excel 안전 빌드가 별도 COM 인스턴스를 점유한 상태에서 위 회귀 검증을 병행해 Excel COM 종료가 장시간 정체됐다. 이 작업이 시작한 `verify_excel_hwpx_export.ps1` PowerShell과 하위 Excel 인스턴스만 종료했으며, 다른 빌드 프로세스는 건드리지 않았다. 따라서 Excel→HWPX의 실제 COM·Kordoc 회귀 실행은 Excel 단독 사용 시간에 다시 수행해야 한다. HWPX 단독 명시 토큰 경로의 ZIP/XML·토큰 0·Kordoc 검증 결과와 원본 보호 증빙은 앞 절의 PASS 기록을 따른다.
