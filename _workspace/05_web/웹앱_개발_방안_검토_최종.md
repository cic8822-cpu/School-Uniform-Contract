## 2. 문제 인식 (기존 계획의 한계)

기존 웹앱 설계에는 다음과 같은 과제가 있음:

1. **개발 난이도 높음**: 백엔드 서버, 데이터베이스, 인증/권한, API 설계, 배포/운영 전부 미시작
2. **서버 운영 부담**: SSL, 도메인, 업데이트, 장애 대응 등 지속적 관리 필요
3. **개인정보 경계 복잡**: 입력값을 서버에 저장하면 전송·저장·삭제 전담 ADR 필수
4. **P2-03 ADR 대기**: 웹앱 HWPX 이관 전제 조건인 "Excel 연계 곤란" 판정이 아직 없음
5. **중복 작업 위험**: 엑셀에서 이미 구현한 출력 로직(VBA 매크로)을 웹에서 재구현해야 함
6. **사용자 의도와 불일치**: 사용자가 "서버 운영은 안 한다"고 명시 → 서버가 필요한 헤드리스 CMS(스트레이트 등)는 적합하지 않음

## 3. 최종 결정: HTML 정적 사이트 기반 아키텍처

### 3.1 선택한 방향

**정적 웹사이트 (HTML/CSS/JS) + 가벼운 백엔드(선택) + 엑셀 별도 배포**

| 항목 | 내용 |
|---|---|
| **프론트엔드** | HTML + CSS + JavaScript (Tailwind CSS 프레임워크 사용) |
| **배포** | Vercel / Netlify / Cloudflare Pages (무료 정적 호스팅) |
| **백엔드** | **선택 사항** — HWPX 생성이 필요할 경우에만 서버리스 함수(Vercel Edge Function) 또는 가벼운 Node.js API |
| **데이터 저장** | 스트레이트(Strapi) 같은 CMS **불필요** — 학교 기초자료는 엑셀 파일 또는 서버리스 함수 내부에만 존재 |
| **HWPX 생성** | `hwpx_token_fill.ps1` 공통 인터페이스로 호출 |
| **엑셀** | 별도 배포 (Microsoft 365 기반 로컬 사용) |

### 3.2 왜 HTML 정적 사이트인가

| 평가 항목 | HTML 정적 사이트 | 스트레이트(Strapi) 헤드리스 CMS |
|---|---|---|
| **서버 운영** | ❌ 불필요 (CDN 정적 호스팅) | ✅ 필요 (Node.js 서버 운영) |
| **데이터베이스** | ❌ 불필요 | ✅ 필요 (PostgreSQL/MongoDB) |
| **백엔드 코드** | ❌ 불필요 (또는 서버리스 함수만) | ✅ 필요 (API 서버) |
| **개발 난이도** | ⬇️ 낮음 (HTML/CSS/JS만) | ⬆️ 중간 (서버 세팅, DB 설계, API) |
| **디자인 자유도** | ⬆️ Tailwind CSS로 완전 커스텀 | 관리자 페이지 별도, 프론트엔드는 별도 구성 |
| **배포** | Vercel/Netlify 무료 정적 호스팅 | Vercel/Heroku에 Node.js 서버 호스팅 (비용 발생) |
| **비용** | 거의 무료 | 월 $5~20 (서버 호스팅) |
| **서버 운영** | **불필요** | **필요** |
| **사용자 의도** | ✅ "서버 운영 안 한다"와 정확히 부합 | ❌ "서버 운영 안 한다"와 충돌 |

**핵심**: 사용자가 "서버 운영은 하지 않겠다"고 명시했으므로, 백엔드 서버와 데이터베이스가 필요한 스트레이트(Strapi)는 원래부터 적합하지 않았습니다.

### 4.2 HWPX 토큰 치환 인터페이스 (공통)

```bash
hwpx_token_fill.ps1 -TemplatePath <hwpx> -JsonPath <학교데이터.json> -OutputPath <출력 hwpx>
```

이 명령어는 **누가 호출하느냐에 관계없이 동일**하게 작동합니다:

| 호출 주체 | 방식 |
|---|---|
| **웹 백엔드** | Node.js에서 `child_process.exec()`로 호출 |
| **엑셀 VBA** | `Shell` 명령으로 PowerShell에서 호출 |
| **데스크탑** | PowerShell에서 직접 수동 호출 |

핵심은 **HWPX 템플릿 + JSON 데이터**라는 인터페이스가 동일하다는 점입니다.

## 5. 작동 흐름

### 5.1 웹 경로 (정적 사이트 + 선택적 백엔드)

```
1. 사용자가 웹사이트 접속
2. 첫 화면: 교복구매 9단계 워크플로우 표시
3. 단계 클릭 → 해당 단계 설명 + 주의사항 + 관련 서식 목록
4. 서식 선택 → "기초자료 입력" 또는 "엑셀 파일 업로드"
   ├── 팝업으로 학교명·학년도 수기 입력 → JS가 JSON 생성
   └── 엑셀 파일 업로드 → 백엔드에서 파싱하여 JSON 추출 (선택)
5. "HWPX 출력" 클릭
   ├── 백엔드가 있다면: hwpx_token_fill.ps1 호출 → HWPX 생성 → 다운로드
   └── 백엔드가 없다면: 엑셀 파일 다운로드 안내 → 사용자가 매크로 실행
6. HWPX 파일 다운로드 완료
```

### 5.2 엑셀 경로 (독립적)

```
1. 사용자가 Excel 파일 열기 (교내 로컬)
2. 기초자료입력 시트에 데이터 입력
3. 서식 탭에서 원하는 Form ID 선택
4. "출력" 버튼 클릭 → VBA 매크로 실행
   ├── Excel PDF 출력 (내장)
   └── HWPX 생성 (hwpx_token_fill.ps1을 Shell로 호출)
5. 파일 저장
```

## 6. 장단점 비교

### 6.1 HTML 정적 사이트 vs 원래 계획(PRD FR-08)

| 평가 항목 | HTML 정적 사이트 (채택) | 원래 계획 (PRD FR-08) |
|---|---|---|
| **서버 운영** | ❌ 불필요 (정적 호스팅) | ✅ 필요 (백엔드 서버 + DB) |
| **데이터 저장** | ❌ 불필요 (또는 서버리스) | ✅ 모든 입력값 서버에 저장 |
| **개인정보 보안** | ✅ 엑셀 파일 자체가 학교 현장에 있음 | ❌ 전송·저장·삭제 ADR 필수 |
| **개발 난이도** | ⬇️ 낮음 | ⬆️ 높음 |
| **디자인 자유도** | ⬆️ Tailwind CSS 완전 커스텀 | ⬆️ 동일 |
| **HWPX 출력** | ✅ `hwpx_token_fill.ps1` 공통 인터페이스 | ✅ 동일 |
| **배포** | Vercel/Netlify 무료 정적 호스팅 | 자체 서버 호스팅 필요 |
| **비용** | 거의 0원 | 월 $5~20 |
| **모바일 대응** | ✅ 반응형 웹 | ✅ 웹 기본 |
| **엑셀 매크로 재사용** | ✅ VBA 이미 구현 완료 | ❌ 웹에서 재구현 필요 |
| **엑셀 독립 사용** | ✅ 파일만 있으면 웹 없이도 작동 | ❌ 웹 의존 |

### 6.2 HTML 정적 사이트의 장점

1. **개발 난이도 낮음**: HTML/CSS/JS만으로 충분, 백엔드 서버/DB/인증 불필요
2. **디자인 우수성**: Tailwind CSS로 현대적이고 깔끔한 UI 구현 가능
3. **배포 용이성**: GitHub → Vercel 연동 자동 배포 (무료)
4. **서버 운영 없음**: 정적 파일만 CDN에 배포하면 됨
5. **이동 속도 빠름**: CDN 캐싱으로 로딩 즉시
6. **유지보수 간편**: 정적 파일만 관리하면 됨
7. **엑셀 매크로 재사용**: VBA가 이미 출력 로직을 가지고 있으므로 재구현 불필요
8. **사용자 의도 부합**: "서버 운영 안 한다"는 요구사항 정확히 충족

### 6.3 HTML 정적 사이트의 한계

1. **HWPX 생성**: 브라우저에서 HWPX 바이너리를 직접 생성하는 건 불가 → 백엔드 함수 필요
   - **해결**: 서버리스 함수(Vercel Edge Function) 또는 엑셀 매크로 경로
2. **실시간 데이터 공유**: 학교 간 기초자료를 공유하려면 백엔드가 필요
   - **해결**: 각 학교가 개별 엑셀 파일을 관리 (원래 방식)

## 7. HWPX 출력 경로 (핵심 결정)

사용자가 "서버 운영을 안 한다"고 했으므로, HWPX 출력은 두 가지 경로로 조율합니다:

| 경로 | 방식 | 서버 필요 | 사용자 편의성 |
|---|---|---|---|
| **경로 A: 엑셀 매크로** | VBA가 `hwpx_token_fill.ps1`을 Shell로 호출 | 불필요 | 사용자가 Excel에서 직접 실행 |
| **경로 B: 서버리스 함수** | Vercel Edge Function에서 `hwpx_token_fill.ps1` 호출 | 가벼운 함수만 | 웹에서 한 번 클릭으로 자동 생성 |
| **경로 C: 수동 다운로드** | 웹에서 HWPX 템플릿 + JSON 다운로드 → 사용자가 PowerShell에서 수동 실행 | 불필요 | 가장 번거로움 |

**권장**: **경로 A + 경로 B 병행**
- 엑셀 사용자는 VBA 매크로로 HWPX 생성 (이미 구현됨)
- 웹 사용자는 서버리스 함수로 HWPX 자동 생성 (최소한의 백엔드)

## 8. 제안 사항

### 8.1 엑셀과 웹앱은 별개로 운영
- 두 플랫폼은 **독립적으로 배포**하며, 서로에게 의존하지 않음
- 엑셀은 학교 내부 로컬에서 사용 (Microsoft 365 기반)
- 웹은 누구나 접근 가능한 정적 사이트

### 8.2 HWPX 자동화는 공통 인터페이스로 연결
- `hwpx_token_fill.ps1`이 두 플랫폼 모두에서 호출 가능한 **유일한 HWPX 생성 엔진**
- 엑셀은 VBA에서 `Shell`로 이 스크립트를 호출
- 웹은 백엔드에서 이 스크립트를 호출
- 핵심은 **HWPX 템플릿 + JSON 데이터**라는 인터페이스가 동일하다는 점

### 8.3 웹은 절차 안내 + 서식 선택에 집중
- 웹의 주요 역할은 **교복구매 9단계 워크플로우 안내** + **서식 목록 제시** + **출력 버튼**
- 기초자료 입력은 팝업(수기 입력) 또는 엑셀 파일 업로드로 처리
- 실제 출력(엑셀·HWPX·PDF)은 엑셀 매크로나 백엔드 스크립트가 담당

### 8.4 서버 운영은 하지 않음
- 정적 사이트 호스팅(Vercel/Netlify/Cloudflare Pages 무료)만 사용
- 백엔드 서버 운영, DB 관리, SSL 인증서 갱신 등 불필요
- **스트레이트(Strapi) 같은 헤드리스 CMS는 사용하지 않음** (서버 운영이 필요하므로)

### 8.5 교내 배포 전략
- 엑셀 파일: GitHub 릴리즈 또는 Google Drive 공유
- 웹: 정적 사이트 URL만 공유 (school-name.hwp-x.app 등)
- 각 학교가 엑셀 파일 + 웹 URL만 가지고 있으면 됨

### 8.6 기술 스택 제안

| 역할 | 기술 | 이유 |
|---|---|---|
| 프론트엔드 | HTML + Tailwind CSS + JavaScript | 가볍고 커스터마이징 용이 |
| 배포 | Vercel | GitHub 연동 자동 배포, 무료 |
| 백엔드 (선택) | Vercel Edge Function | 서버리스, 서버 관리 불필요 |
| HWPX 생성 | `hwpx_token_fill.ps1` | 이미 구현된 공통 인터페이스 |

## 10. 결론

1. **엑셀과 웹앱은 별개 운영**이 맞음 — 두 플랫폼 모두 독립적으로 사용 가능
2. **HWPX 자동화는 공통 인터페이스(`hwpx_token_fill.ps1`)**로 연결하면 엑셀이든 웹이든 상관없이 작동
3. **HTML 정적 사이트(Tailwind CSS)가 최선의 웹 방식** — 서버 운영 불필요, 디자인 자유도 높음, 개발 난이도 낮음
4. **스트레이트(Strapi)와 같은 헤드리스 CMS는 부적합** — 서버 운영이 필요하므로 사용자 의도("서버 운영 안 함")와 충돌
5. **Vercel/Netlify 무료 정적 호스팅**으로 배포 완전 무료
6. 엑셀의 VBA 매크로를 재사용하므로 **웹에서 출력 로직을 재구현할 필요 없음**
