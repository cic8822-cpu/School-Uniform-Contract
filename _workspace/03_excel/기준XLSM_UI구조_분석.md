## 3. 핵심 발견 — P3-01 재설계에 영향

1. **"실무 입력 화면"은 워크시트 셀 입력이 아니라 VBA UserForm(모달 대화상자) 기반임.** 특히 `UserForm2`(2,779줄)가 기초자료 공통값 입력의 실체로 추정되며, 현재 `artifacts/excel/교복구매_길라잡이_MVP_초안.xlsm`(구조 초안)이 제공하는 "시트 범위 입력" 방식과는 UX 수준이 근본적으로 다름. 이것이 P3-01 완료 철회의 실질적 원인으로 확인됨.
2. **계약(용역) 유형별 추가 입력 서브폼이 존재함**(`유저폼_용역_현장체험학습`). `Rtable_용역`(409행) 드롭다운에서 특정 유형을 고르면 유형 전용 추가 필드를 입력받는 구조로 추정됨 — 단일 공통 입력 화면만으로는 기준 기능에 못 미침.
3. **학교 검색은 전용 대화상자로 처리됨**(`소속기관검색폼`, `학교정보` 1,516행 DB 대상). `Ref_data`의 8개 이름정의(학교명/주소/전화/홈페이지 등)가 모두 `#REF!`로 깨진 것은 이 검색폼이 Ref_data 수식 대신 직접 DB를 조회·기록하는 방식으로 바뀌었기 때문일 가능성이 높음(추정, VBA 소스 확인 필요).
4. **"선택 출력"은 시트 분리가 아니라 단일 거대 시트(`계약서식`, 703행)의 특정 구간을 선택해 인쇄영역을 갱신하는 방식으로 추정됨.** `Print_sheet`(숨김, 코드비하인드 없음)가 스테이징 용도로 쓰이고, 실제 범위 지정/인쇄 제어는 `Module1` 또는 `Sheet3`(메인 메뉴) 코드에서 수행하는 것으로 보임(추정, VBA 소스 확인 필요).
5. **외부 링크·깨진 이름정의는 재확인됨**: `Rtable_용역!Drop_1`/`Drop_2`가 존재하지 않는 OneDrive 경로(`[계약길잡이_v3.0.xlsm]Rtable_A`)를 가리키는 시트 범위 이름과, 이를 대체하는 로컬 워크북 범위 이름(`Drop_1`/`Drop_2` → `Rtable_A!...`)이 공존함. 클린룸 재구현 시 워크북 범위 이름 방식만 채택하고 외부 경로 참조는 원천 배제함(원칙 준수).

### 6.1 핵심 정정 — 1차 분석의 "UserForm2 = 기초자료 공통 입력 모달" 가설은 틀림

실제 구조는 다음과 같음:

1. **"기본정보 입력하기"(Sheet6)가 실무 입력 화면의 실체임.** UserForm 모달이 아니라 **시트 셀에 직접 입력**하는 방식이며, `Module1`의 `데이터입력_신규하기`/`데이터입력_저장하기`/`데이터입력_수정하기`/`선택한공사정보_가져오기`가 `Sheet6.Cells(row,col)` ↔ `Sheet7("DB").Cells(row,col)` 간에 직접 값을 복사함(수식이 아닌 VBA 대입).
2. **UserForm2(2,779줄)는 "계약절차안내" 팝업임.** 용도는 사용자가 Sheet1에서 계약방법(1인견적/2인견적/입찰)을 클릭했을 때, 해당 계약유형·방법에 대응하는 **17단계 절차 버튼(CommandButton1~17)**과 단계별 상세설명·첨부파일·관련법규 링크를 참조시트에서 읽어와 보여주는 **모덜리스 안내창**임. 기초자료 입력과 무관함.
3. **`Sheet3`(코드명, 탭 표시명 "Sheet1")는 "계약방법 결정 마법사" 로직임.** `드롭다운1`(계약분야: 물품=2/용역=3/공사=4, `Sheet1!V4`) → `드롭다운2`(계약유형, `Sheet1!V6`) → `추정가격`(`Sheet1!I5`) 입력 후 `submit()`이 계약유형별 가격 구간 규정(예: 2천만원 이하/2천만~5천만/5천만 초과)에 따라 1인견적·2인견적·입찰 버튼의 노출/비활성 여부와 캡션을 동적으로 계산함. 버튼 클릭 시 참조시트(`Rtable_물품`/`Rtable_용역`/`Rtable_공사`) 행 오프셋을 계산해 UserForm2에 전달함.
4. **`소속기관검색폼`은 학교 검색 전용 모덜리스 폼임.** `학교정보`시트(A2부터, 열: 번호/지역/급별/설립/학교명/주소/연락처) 1,516행을 `TextBox1` 입력값으로 필터링해 리스트박스에 표시하고, 더블클릭 시 `Sheet6`의 지역/유형/학교명/주소/학교급 셀에 직접 기록함. `Module1.소속기관검색하기()`가 `.Show vbModeless`로 호출함. `Ref_data`의 8개 `#REF!` 이름정의(학교명/주소/전화 등)는 이 폼이 대체한 것으로 확인됨(가설 확정).

### 6.2 중대 결함 발견 — 기준 XLSM 자체가 "용역"만 동작하고 "물품/공사"는 깨져 있음

- `Sheet3.submit()`/`CommandButton1~3_Click`의 분기 로직은 `IntDrop_1`(계약분야) 값에 따라 `varDataSheet = "Rtable_물품"` 또는 `"Rtable_공사"`를 참조하도록 되어 있으나, **이 워크북에는 `Rtable_용역` 시트만 존재하고 `Rtable_물품`/`Rtable_공사` 시트는 없음**(1장 "워크시트 구성" 목록 참고). 즉 계약분야로 "물품" 또는 "공사"를 선택하면 `Sheets("Rtable_물품")` 참조에서 런타임 오류가 발생하는 **깨진 경로**임.
- **교복구매는 물품 분야(Drop_1=2)·계약유형 코드 3에 해당함**(`Rtable_A!G5="교복구매"`, `Sheet3.submit()` 주석에 `IntDrop_2 = "3" → "교복"`으로 명시됨). 즉 **기준 XLSM은 이 프로젝트의 실제 대상 시나리오(교복 물품구매)를 시연할 수 없는 상태**이며, "용역계약갈라잡이" 파일명대로 용역(서비스) 계약 절차만 실제로 동작함.
- `UserForm2.CommandButton_mini/mini2/mini3_Click`이 참조하는 `UserForm_popup_적격심사`, `UserForm_popup_적격심사_용역`, `UserForm_popup_계약이행능력심사`, 그리고 `Sheet3.popup()`이 참조하는 `UserForm_popup_우유_사전절차` 등 9개 사전절차 폼도 **VBA 컴포넌트 목록에 존재하지 않음**(죽은 참조). 이 워크북은 더 큰 "계약길잡이" 계열 템플릿에서 용역 부분만 남기고 축소한 사본으로 추정됨.
- **결론**: 기준 XLSM은 "메커니즘(마법사 흐름·절차안내 팝업·서식선택 체크박스·인쇄)의 원형"으로는 유효하지만, **교복구매(물품) 관련 실제 콘텐츠(절차 텍스트·참고법령·첨부파일명)는 이 파일에 없음**. 교복 관련 콘텐츠는 `교복4차 (2)/*.hwpx` 매뉴얼에서 가져와야 하며, 이는 `document-automation-engineer`/`uniform-workflow-analyst` 산출물(`서식_인벤토리.md`, `서식_매핑표.md`, `입력데이터_사전.md`)과 연결해야 함.

### 6.3 "서식 선택·출력" 메커니즘 — 완전히 확정됨(재사용 가능한 패턴)

`Sheet6`(AF~AK열)의 실제 수식을 확인한 결과, 서식선택은 **20개 체크박스 × 22페이지** 매핑으로 동작함:

- 체크박스 20개: `AG12`~`AG22`(11개) + `AH12`~`AH20`(9개), 각각 `1/0` 값을 가짐(체크박스 클릭 이벤트가 `Sheet6.Range("AGnn").Value = 현재값 ± 1`로 갱신).
- 페이지 매핑 수식(예): `AJ12 = IF(AG12=1, "A1:BD33,","")`, `AJ13 = IF(AG13=1, "A34:BD68,","")` … `AJ22 = IF(AG22=1, "A327:BD357,","")`. `AH`쪽 체크박스도 동일 패턴(`AK`열, 이번 확인에서 열 위치까지는 못 읽었으나 `현재_통합_문서`의 `HPageBreaks` 위치로 역산 가능).
- `AF1 = AJ12&…&AJ22&AK12&…&AK20`(모든 조각 이어붙임), `AF2 = IF(RIGHT(AF1,1)=",", LEFT(AF1,LEN(AF1)-1), AF1)`(끝 콤마 제거) → **다중 영역 인쇄범위 문자열**.
- `AH21 = SUM(AG12:AG22, AH12:AH20)` → 선택된 서식 개수(0이면 "출력할 서식을 1개 이상 선택하세요" 경고).
- `Module1.PrintSpecificPage()`가 `Sheet6!AH21=0` 검사 후 `Sheet12.Range(Sheet6!AF2).PrintPreview`를 실행함(다중 영역 Range를 문자열로 조립해 한 번에 미리보기).
- **주의**: `Sheet6`의 체크박스 클릭 이벤트(`Private Sub CommandButton1_Click`, 22개 서식을 `서식출력(from,to)`로 개별 인쇄하던 이전 방식)는 **현재 주석 처리되어 비활성 상태**임. 즉 기준 XLSM 자체도 "선택 출력" UI 버튼이 죽어 있고, `AF2` 기반의 새 방식만 동작함.

### 6.4 기초자료 입력 필드 — Sheet6/Sheet7 완전 확정(원본 필드셋, 참고용)

`Module1`의 `데이터입력_신규하기`/`데이터입력_저장하기` 주석과 실제 셀 좌표 확인으로 32개 필드가 Sheet6(입력) ↔ Sheet7(DB, 1행=1레코드) 간 1:1 대응함을 확인함(예: `Sheet6!G13`=용역명 ↔ `Sheet7` 2열, `Sheet6!G20`=계약업체명 ↔ `Sheet7` 11열 … `Sheet6!AA32`=계약방법 ↔ `Sheet7` 32열, 33열은 자동생성 "용역구분키"). 이 필드셋은 **용역 행정계약용**이며, 교복구매 프로젝트의 실제 데이터 모델은 이미 `입력데이터_사전.md`에 `C-01~C-06`(공통)/`B-01~B-07`(사업)/`D-01~D-05`(문서별)/`R-01~R-07`(반복)/`K-01~K-04`(계산)로 별도 확정되어 있으므로, **Sheet6 필드셋을 그대로 이식하지 않고 C/B/D/R/K 계약을 기준으로 새 "기초자료" 시트를 설계함**. Sheet6 구조는 "신규/저장/수정/불러오기" 매크로 패턴과 체크박스형 서식선택 UI 배치 참고용으로만 재사용함.

> 확인 중 Sheet6에 실제 샘플(테스트) 계약 데이터가 입력된 상태를 발견함(업체명·주소·사업자등록번호·계좌번호·담당자명 등). `CLAUDE.md`의 데이터 경계 원칙에 따라 **구체적 샘플 값은 이 문서·로그·커밋에 원문으로 남기지 않았음**(필드 위치·라벨만 기록). 새 워크북에는 이 샘플 데이터를 이식하지 않고 빈 칸으로 유지함.
