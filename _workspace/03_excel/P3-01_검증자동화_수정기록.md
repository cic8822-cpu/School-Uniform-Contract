# P3-01 Excel 검증 자동화 수정 기록

- 작업일: 2026-09-15
- 대상: `artifacts/excel/교복구매_길라잡이_Excel_v1.xlsm`, `scripts/build_excel_v1_structure.ps1`, `scripts/build_excel_v1_vba.ps1`
- 원본 XLSM/HWPX: 수정하지 않음

## 수정 내용

1. 구조 빌더에 F-007/F-024 원문 대조 v2 재적용 단계를 추가했다. 따라서 빌더를 재실행해도 구 초안(F-007 제목 C8, F-024 금액 합계 F18)으로 되돌아가지 않는다.
2. 일반 사용 매크로의 메시지 UX는 유지하면서, 검증 전용 무대화식 매크로를 추가했다.
   - `검증_저장하기` → DB 저장만 수행
   - `검증_초기화` → 입력 초기화만 수행
   - `검증_선택서식_PDF저장` → 선택 서식 PDF 생성만 수행
   - 기존 `저장하기`, `초기화`, `선택서식_PDF저장`은 내부 실행 프로시저에 `showMessage=True`를 전달하므로 기존 MsgBox를 유지한다.

## 검증 증거

- PowerShell AST 파서: 두 빌더 스크립트 오류 0건.
- Excel COM으로 배포본을 읽기 전용 재열어 `Module_기초자료`의 `저장하기`/`검증_저장하기`/`초기화`/`검증_초기화` 및 `Module_출력`의 `선택서식_PDF저장`/`검증_선택서식_PDF저장` 프로시저 존재를 확인했다.
- 검증 사본에서 마스킹 값(테스트초등학교, 2026학년도, 품목 단가 50,000/40,000)을 입력하고 대화상자 없이 다음을 확인했다.
  - `검증_저장하기`: DB 2행에 순번 1, 학교명 테스트초등학교 저장
  - F-007 `C9`: `2026학년도 동복 학교주관구매 요청`
  - F-024 `D15`: 204. 미입력 품목 4행의 기본 수량 1이 포함되는 원문 대조 v2 수식 결과다.
  - F-024 `E9`/`E10`: `55.6%`/`44.4%`
  - `검증_선택서식_PDF저장`: 검증 사본의 자체 경로 `.../_validation_p3_wrapper/output/`에 95,293 byte PDF 1개 생성
  - `검증_초기화`: 기초자료입력 `C4`가 공백으로 초기화됨

## PDF 경로 판정

PDF 매크로는 `ThisWorkbook.Path & "\\output\\"`를 사용한다. 따라서 검증 사본을 `artifacts/excel/_validation...`에 열면 PDF는 그 사본 하위 `output`에만 생성되고, 배포본 `artifacts/excel/output`에는 새 테스트 데이터 PDF가 생성되지 않는다. 검증용 사본과 PDF는 검증 종료 후 제거해야 한다.

## 검증 사본 정리 및 최종 재열기

- 검증 사본 `artifacts/excel/_validation_p3_wrapper`와 그 하위 마스킹 PDF를 제거했다.
- 검증 사본에 연결된 Excel 자동화 프로세스 PID 12508, 21076만 종료했다. 기존 배포본 작업 프로세스 PID 25640은 종료하지 않았다.
- 배포본을 읽기 전용으로 재열어 다음을 확인했다: 파일 크기 59,164 byte, DB 2행 공백, 외부 링크 0, 외부 연결 0, `#REF!` 이름 정의 0, F-007/F-024 Zoom=100, 검증용 매크로 3개 존재.

## 배포 경로 테스트 파일 정리

- 독립 QA가 배포 부적합으로 지적한 합성 테스트 PDF 두 개만 제거했다.
  - `선택서식_20260915_202755.pdf` (73,415 byte)
  - `선택서식_20260915_223017.pdf` (94,612 byte)
- 제거 후 `artifacts/excel/output` 폴더는 유지되며 파일 수는 0개다. XLSM은 변경하지 않았다.

## 검증 스크립트 정합성 주의

현재 `scripts/verify_excel_v1.ps1`의 구 기대값(F-007 `C8`, F-024 `F18=9,000,000`)은 원문 대조 v2 레이아웃과 불일치한다. v2 기준 검증값은 F-007 `C9` 제목 연동, F-024 `D15` 수량 합계 및 `E9:E14` 단가비율 수식이다. 스크립트 소유자가 이를 반영해야 전체 검증이 통과한다.
