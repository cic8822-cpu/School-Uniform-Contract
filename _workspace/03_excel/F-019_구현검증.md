## 중단·재개 경위

- 이전 세션에서 F-019 구조·VBA·검증 스크립트 초안까지 작성했으나, Excel COM 자동화가 중복 프로세스와 VBA 중단 상태를 일으켜 새 XLSM 저장 및 PDF 수동 QA를 완료하지 못하고 중단함(중단 당시 기록은 `로그.md` 2026-09-17 "F-019 입찰참가신청서 구현 중단" 참고).
- 재개 세션 시작 시 좀비 가능성이 있던 EXCEL.EXE 2개를 사용자 승인 하에 종료함(`taskkill /F /IM EXCEL.EXE`). 이후 각 Excel COM 스크립트 실행 전후로 `Get-Process -Name EXCEL`을 직접 확인해 단일 세션만 유지함.

## 발견·수정한 실제 결함 (A4 1쪽 조판)

1. **1차 안전 빌드**: 구조·VBA는 정상 완료했으나 `verify_excel_v1.ps1`이 `F-019_입찰참가신청서 A4 1쪽 자연 배율 출력`에서 `FAIL`. 로그: `Zoom=100, HPageBreaks=1, VPageBreaks=0`. 원인은 F-019 시트만 `PageSetup.Orientation=2`(가로)로 설정되어 있었던 것(다른 구현 서식은 모두 세로).
2. **2차 시도(세로 전환)**: `Orientation=1`로 변경 후 재실행했으나 이번에는 `HPageBreaks=0, VPageBreaks=1`(폭 초과)로 실패. 열 너비 합(약 18.1cm)이 세로 가용 폭(약 19.4cm)에 근접해 실제 여유가 부족했음.
3. **원인 정밀 진단**: 전체 파이프라인 재실행 대신 직전 실패로 남은 스테이징 파일(`artifacts/excel/build.xlsm`) 사본을 열어 F-019 시트의 `PageSetup`·`HPageBreaks.Location`·행 높이·열 너비를 COM으로 직접 조회함. 가로 방향 기준 총 행 높이 547.5pt(19.32cm), 가용 높이 약 19.4cm로 여유가 2.4pt에 불과함을 확인.
4. **수정**: 가로 방향(`Orientation=2`)을 유지하고 행 높이를 재조정함 — 안내문 1·2행 16.5pt→10pt, 6~11행 26pt→23pt, 13행 44pt→40pt, 20행 52pt→46pt(총 530.5pt). 같은 COM 진단 스크립트로 동일 시트에 후보 값을 직접 적용해 `HPageBreaks=0, VPageBreaks=0`을 먼저 확인한 뒤 `scripts/build_excel_v1_structure.ps1`에 반영함.
