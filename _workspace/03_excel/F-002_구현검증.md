## 구현 범위와 발견한 버그

- `scripts/build_excel_v1_structure.ps1`에 `F-002_위원수락확인서` 시트를 F-001 뒤에 추가함(`$implemented`
  해시 등록). 제목 → 3단락 본문 → 날짜 → 주소/성명/서명(공란) → 수신처 구조로 단순 텍스트 서식임.
- **버그 발견·수정(1차)**: 최초 구현에서 본문 3단락을 `B6:E9`(4행) 하나의 병합 셀에 `CHAR(10)`으로
  줄바꿈해 넣었는데, 비식별 PDF 1차 육안 확인에서 텍스트 상단·하단이 잘려 보이는 결함을 발견함.
  원인은 WrapText가 켜진 다중행 병합 셀은 인쇄 시 행 높이가 자동으로 늘어나지 않고 고정 높이 안에서
  잘린다는 점(고정 `RowHeight` 사용). 조치: 단락마다 별도의 단일행 병합(B6:E6/B7:E7/B8:E8)으로 나누고
  `Rows.AutoFit()`으로 각 행 높이를 자동 계산하도록 재구성함. 동시에 A4 폭 초과(`VPageBreaks=1`)도
  발견해(여백 1.5cm→1.0cm로 조정, F-025와 동일 여백) 함께 해결함.
- **버그 발견·수정(2차, 더 근본적)**: 1차 수정 후 재빌드에서 검증 스크립트가 다시 실패함. COM으로
  직접 확인한 결과, 3개의 독립된 단일행 병합(B6:E6/B7:E7/B8:E8)을 만든 뒤 `$ws.Range("B6:B8").WrapText
  = $true`처럼 병합 경계를 벗어나는 부분 범위(B열 3행, 병합은 B:E 4열)에 서식을 한 번에 설정하자
  Excel이 세 병합을 하나의 `B6:E8` 병합으로 자동 통합해버려 B7·B8의 내용이 사라지는 것을 확인함
  (COM으로 `MergeArea.Address()`를 직접 조회해 `$B$6:$E$8`로 병합돼 있음을 확인·재현). 조치:
  `WrapText`·`VerticalAlignment` 설정을 각 행(B6, B7, B8)에 개별적으로 적용하도록 변경해 해결함.
  Borders 속성은 F-025 등 기존 서식에서 이미 다중 병합에 걸친 전체 범위(`B6:E8` 형태) 지정이 문제
  없이 동작해 왔으므로 그대로 유지함(이번 결함은 병합 폭(B:E)과 정확히 일치하지 않는 부분 범위(B만)에
  서식을 적용할 때만 발생하는 것으로 판단).
- `scripts/build_excel_v1_vba.ps1`에 `검증_F002출력가능()`(= `검증_필수값검증()`만 요구, 위원 반복행이나
