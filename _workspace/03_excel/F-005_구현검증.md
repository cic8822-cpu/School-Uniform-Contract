## 구현 방식: 콘텐츠 스트림 기반 행 빌더

- 6쪽 분량의 장문 문서를 관리하기 위해 `F005Row` 헬퍼 함수를 새로 작성함. 콘텐츠를
  `F005Row '종류' '값1' '값2' '값3'` 형태로 순서대로 호출하면 함수가 행 번호를 자동 증가시키며
  제목(title)/장 표제(h1)/소제목(h2)/문단(item)/각주(note)/spacer(blank)/3열 표 헤더·행
  (table3header/table3row)을 각각의 서식으로 셀에 기록한다. 개별 셀 주소를 일일이 계산하지 않아도
  되므로 대량의 정적 텍스트를 다루는 이런 유형의 서식에 재사용 가능한 패턴임.

## 발견한 결함 3건과 근본 수정(전부 이번 세션에서 새로 발견)

1. **`.Formula`/`.Value2` 혼용 실수**: 콘텐츠 스트림 다수를 Excel 수식 문자열 리터럴 표기
   (`"..."`, 앞에 `=` 없음)로 작성했는데, `.Formula` 속성은 `=`로 시작하지 않으면 그 문자열을
   그대로(따옴표 문자 포함) 리터럴 텍스트로 저장한다는 점을 놓쳐, 화면에 따옴표 문자가 그대로
   노출되는 결함을 발견함. `F005SetCell` 헬퍼를 추가해 `=`로 시작하면 수식으로, 아니면 앞뒤 따옴표를
   제거한 뒤 `.Value2`로 쓰도록 통일해 해결함.
2. **`Rows.AutoFit()`이 병합 셀 줄바꿈 높이를 정확히 계산하지 못함(Excel 자체의 알려진 한계)**:
   1차 PDF 육안 확인에서 여러 줄로 감싼 문단과 표 셀의 행 높이가 한 줄 높이(17.4pt)에 머물러 뒷부분이
   잘리는 결함을 발견함. `Rows.AutoFit()`은 한 행에 병합 셀이 여러 개 있거나 폭이 넓은 병합 셀의
   경우 줄바꿈 높이를 제대로 계산하지 못하는 것으로 알려져 있다(Microsoft 공식 문서에도 기재된
   제약). AutoFit에 의존하는 대신 텍스트 길이·병합 폭 기준으로 필요한 줄 수를 추정해 행 높이를
   직접 계산하는 방식(`F005LineCount` 헬퍼)으로 전면 교체함.
3. **한글 곡선 따옴표(‘ ’, U+2018/U+2019)가 PowerShell 문자열 파싱을 깨뜨림**: 2차 수정 후에도
   특정 4개 문장에서 텍스트가 곡선 따옴표 직전에서 잘리는 결함이 재현됨(F-003의 `@()` 배열 붕괴와
   같은 계열의 `[scriptblock]::Create()` 실행 경로 인코딩 문제로 추정). 격리 디버그로 확인 후, 이미
   이 프로젝트에서 안전하게 쓰이고 있던 「」(홑화살괄호, F-003에서 이미 사용 검증됨)로 4곳 전부
   교체해 해결함. **재발 방지**: 이 스크립트에서 한글 인용부호가 필요하면 반드시 「」를 쓰고, ‘ ’는
   사용하지 않는다.
