  7행 예시: 위원장 1 + 위원 6) → "붙임 1.…확인서 1부. 2.…서약서 1부. 끝." → 결재란(담당/협조자/교장,

## 개인정보 경계와 위원 반복행 재사용 판단

- 원문 "라. 위원 명단" 표의 "성명" 열은 실제 이름(예: 홍길동)이 들어가는 개인정보 필드이므로
  `입력데이터_사전.md` R-02 원칙(실제 성명 자동 입력 금지)에 따라 마스킹 식별표시만 반영함.
- **DB_위원 재사용 여부 판단**: `기초자료입력!B58:C67`("6. 위원 반복행" — 역할·직위 / 마스킹
  식별표시)과 `DB_위원` 시트는 P3-01 초기(F-014~016 평가 인프라 작업 시점)에 R-01/R-02 공용
  저장소로 이미 마련돼 있었으나, 실제로는 F-014/F-015/F-016 중 어느 서식도 이 반복행을 소비하지
  않고 있었음(세 서식 모두 R-04/R-07만 사용, `서식_매핑표.md` 확인). `입력데이터_사전.md`도 R-02
  적용 대상을 "F-001~F-003, F-034~F-040"으로 명시하고 있어, 이번 F-001이 이 공용 저장소의 **첫
  실제 소비자**임을 확인함. 별도 `DB_교복선정위원` 신설 대신 기존 `기초자료입력`·`DB_위원`을
  그대로 재사용하기로 결정함(기초자료입력 입력 UI·기존 VBA 검증 로직은 변경하지 않음).
- 마스킹 허용 형식은 기존 `마스킹식별표시허용()` 함수가 이미 정의한 `위원 ○○`/`위원 **`/`위원 ○*`/
  `위원 *○`(및 평가위원 접두 변형)만 허용함. `입력데이터_사전.md`가 R-02 형식을 "위원 A~위원 J"로
  서술한 것과 표기가 다른 불일치를 발견했으나, 기존 VBA 로직(`위원행검증`/`마스킹식별표시허용`)은
  이미 F-014~016 설계 당시부터 구현돼 있었고 이번 작업 지침상 "기존 VBA 로직은 변경하지 않는다"는
  제약이 있어 **기존 구현(○○/**/○*/*○ 기호 방식)을 그대로 따름**. 데이터 사전 문구(A~J 영문 방식)와
  실제 구현의 표기 불일치는 기록만 하고 수정하지 않음(P1 재검토 과제로 남김).
- "구분"(위원장/위원)은 원문 표에서 첫 행만 위원장인 고정 서식이므로, 입력 시트에 별도 필드를
  추가하지 않고 출력 시트에서 **첫 번째 채워진 행을 위원장, 나머지를 위원으로 파생**하는 수식으로
  처리함(기초자료입력 입력 UI 변경 없음).
