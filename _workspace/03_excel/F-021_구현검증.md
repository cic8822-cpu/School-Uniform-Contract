## 2차 세션(재검증) 발견·수정 사항 — 빌드 차단 결함

- **증상**: 이전 세션에서 이미 작성돼 있던 F-022(교복 납품 실적표) 섹션 때문에 `scripts/build_excel_v1_structure.ps1` 전체 실행이 F-021 완료 직후 `'System.Int32' 형식 개체를 'System.String' 형식으로 캐스팅할 수 없습니다` 오류로 중단되어, 안전 빌드 파이프라인이 최종 산출물을 저장하지 못하는 상태였음(F-021 자체는 아님, F-022 헤더 행 작성 루프에서 발생).
- **원인 규명**: 격리 재현으로 좁힌 결과, `for ($i=0; $i -lt N; $i++) { $ws.Cells.Item(row, $i+2)... }` 형태로 루프 변수 기반 컬럼 인덱스를 사용해 `.Cells.Item()`을 반복 호출한 직후, 같은 워크시트의 무관한 셀에 정수를 `Value2`로 대입하는 후속 코드가 이 캐스팅 오류로 실패하는 재현 가능한 PowerShell 5.1 COM 상호운용 이상 동작을 확인함(격리된 최소 재현에서는 간헐적이었으나 실제 950행 규모의 전체 스크립트 컨텍스트에서는 100% 재현됨). 근본 매커니즘은 명확히 규명하지 못했으나, 루프 변수 기반 컬럼 인덱스를 리터럴 `.Range("B$r")`/개별 문자열 주소로 바꾸면 해소됨을 확인함.
- **수정**: `scripts/build_excel_v1_structure.ps1`의 F-022 헤더 행(9행)·순번 열(B10:B17) 작성 코드를 반복문 기반 `.Cells.Item()` 호출에서 리터럴 `.Range("B9")`~`.Range("G9")`, `.Range("B10")`~`.Range("B17")` 개별 대입으로 재작성함(값과 서식은 동일하게 유지). 추가로 F-022가 A4 1쪽을 초과(`VPageBreaks=1`)하던 문제를 열 너비 축소(C:25→20, D:17→14, E:14→12, F:18→15, G:15→13)와 좌우 여백 축소(0.9cm→0.6cm)로 해소함.
- **범위 경계**: F-022는 이번 작업 범위가 아니므로, 위 수정은 안전 빌드 전체를 통과시키는 데 필요한 최소 수정(타입 오류·페이지 초과)에 한정했고, F-022의 내용·원문 대조·개인정보 경계에 대한 별도 검증이나 완료 처리는 하지 않음. F-022는 여전히 별도 구현·검증 세션이 필요함.
- **재검증**: 수정 후 안전 빌드 전체(구조→VBA→검증)를 재실행해 `verify_v1_log.txt` 146개 항목 전부 PASS(FAIL 0건)를 확인함 — F-007·F-014~F-020·F-024·DB 저장/수정/불러오기 회귀 없음, F-021·F-022 관련 검사 포함.
