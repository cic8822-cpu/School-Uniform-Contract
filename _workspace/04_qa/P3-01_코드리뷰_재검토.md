# P3-01 변경 후 High/Critical 재검토

## 확인된 개선

- F-038은 `기초자료입력!B44:B53`의 최대 10개 업체를 `B9:B18`에 반영하며, 대표자·전화·대리인 열은 빈칸으로 유지한다. 검증기도 1행과 10행을 모두 확인한다. (`scripts/build_excel_v1_structure.ps1:1629-1648`, `scripts/verify_excel_v1.ps1:331-339`)
- F-041~F-043은 이전처럼 업체명만으로 출력하지 않고 금액/수량/기한의 존재·양수 조건을 확인하며, 빈 금액 음성 검증도 추가됐다. (`scripts/build_excel_v1_vba.ps1:1415-1439`, `scripts/verify_excel_v1.ps1:359-397`)
- HWPX 토큰 스크립트는 GUID 임시 파일에서 ZIP/XML/잔존 토큰 검증 후에만 결과를 원자적으로 교체하며, Kordoc 버전도 `4.13.1`로 고정됐다. (`scripts/hwpx_token_fill.ps1:132-177`, `scripts/verify_hwpx_token_fill.ps1:19-20,80-83`)
- PostToolUse는 `-Mode static`으로 경량화됐고, `scripts/*.ps1` 전체가 PowerShell 파서·PSScriptAnalyzer 검사 대상이다. (`.claude/settings.json:3-20`, `.claude/hooks/verify-phase.ps1:325-389`)
- 읽기 전용 정적 재검증에서 모든 대상 스크립트의 PowerShell 파서 및 PSScriptAnalyzer Error/Warning 검사가 통과했고, `git diff --check`도 오류 없이 끝났다(CRLF 안내만 출력). 기존 검증 로그에는 Excel v1 전체 PASS가 남아 있다.

## Critical

### CR-R01 — F-042가 계약체결금액과 단가×예정수량의 일치를 검증하지 않음

**파일:** `scripts/build_excel_v1_vba.ps1:1422-1427`; `scripts/verify_excel_v1.ps1:376-380`

**근거:** F-042 출력 가능 함수는 단가 `D17`, 예정수량 `E17`, 계약체결금액 `F17`가 각각 양수인지 확인할 뿐, `F17 = D17 × E17`을 확인하지 않는다. 따라서 예를 들어 단가 44,000원·예정수량 100·계약체결금액 1원도 출력 가능하다. 새 회귀 검증도 정상 조합과 빈 `F17`만 확인한다.

**영향:** 잘못된 계약체결금액이 포함된 낙찰 통보 PDF를 생성할 수 있는 재무·행정 문서 오류다.

**수정:** F-042에 `양수 정수` 검증과 `CLng(D17) * CLng(E17) = CLng(F17)`(오버플로 방지를 위해 `CDbl` 또는 Currency 사용) 검증을 추가하고, 불일치·소수·음수·0값을 모두 거부하는 회귀 테스트를 추가한다.

## High

### HR-R01 — full 품질 훅은 여전히 30초 제한·락 없이 TaskCompleted와 Stop에서 각각 실행됨

**파일:** `.claude/settings.json:22-46`; `.claude/hooks/verify-phase.ps1:357-389`; `scripts/verify_excel_v1.ps1:16-34,708-724`

**근거:** Write/Edit의 반복 full 실행은 static 모드로 분리되어 개선됐지만, `TaskCompleted`와 `Stop` 모두 default `full`을 호출하고 timeout은 30초다. full 모드는 Excel COM·PDF 출력과 검증 폴더 삭제/재생성을 수행하며 단일 실행 락이 없다. 두 이벤트가 겹치거나 30초를 넘으면 기존에 보고된 검증 디렉터리·로그 경합이 마지막 단계에서 재발할 수 있다.

**영향:** 최종 품질 게이트가 시간 초과 또는 동시 실행에 의해 비결정적으로 실패하거나, PASS 로그가 다른 full 실행에 의해 지워질 수 있다.

**수정:** full 훅은 하나의 종료 이벤트만 사용하거나, 별도 명시 실행/CI에서만 수행한다. 실행 중인 full 검증을 막는 원자적 락과 실행별 고유 로그·검증 디렉터리를 도입하고, 실제 Excel/PDF 검증 시간에 맞춰 timeout을 조정한다.
