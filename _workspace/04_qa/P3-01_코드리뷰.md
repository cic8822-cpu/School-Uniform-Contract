# P3-01 Excel·HWPX 자동화 독립 코드 리뷰

## 결론

현재 구현은 일부 Excel 서식의 기초자료 반영·선택 PDF 저장을 제공하지만, 요청한 “기초자료 → Excel/HWPX 전 서식 자동 반영 → A4/PDF 검증” 완료 상태로 판단할 수 없다. `test.md`의 X-06도 여전히 `FAIL`이다. 아래 Critical 항목을 해결하고, Major 항목의 회귀 테스트를 추가하기 전에는 P3-01 완료나 다음 단계 진행을 차단해야 한다.

검토는 읽기 전용으로 수행했으며 원본 XLSM/HWPX 및 배포 산출물은 수정하지 않았다. PowerShell 파서 검사는 대상 스크립트에서 통과했다. PSScriptAnalyzer 1.25.0은 `run_excel_mvp_utf8.ps1`의 `PSAvoidUsingInvokeExpression`, 구조 빌더 및 HWPX 재현 스크립트의 빈 `catch`를 보고했다.

## Critical

### CR-01 — 금액·수량이 비어도 F-041~F-043을 출력할 수 있음

**파일:** `scripts/build_excel_v1_vba.ps1:1406-1415`

**근거:** 세 출력 가능 함수는 공통 필수값과 낙찰 업체명만 확인한다. 그러나 F-041은 예정가격·투찰금액·낙찰률을 직접 입력하도록 만들었고(`scripts/build_excel_v1_structure.ps1:1479,1486-1487`), F-042도 단가·계약체결금액을 직접 입력한다(`:1526-1528`). F-043의 계약단가는 `C16` 직접 입력값인데(`:1571-1574`), 출력 가능 함수는 단가·예정수량·납품기한을 확인하지 않는다.

**영향:** 계약·낙찰 관련 금액이 빈칸이거나 숫자가 아닌 상태에서도 선택 PDF가 생성된다. 빈 계약금액 또는 잘못된 금액이 포함된 행정 문서가 출력될 수 있다.

**수정:** Form ID별 필수 필드를 명시한 검증 함수를 만들고, `검증_F041출력가능`·`검증_F042출력가능`·`검증_F043출력가능`에 양수/정수 범위, 계산 결과, 날짜를 모두 연결한다. 각 Form에 대해 “업체만 있고 금액·수량이 없는 경우 선택/PDF가 거부됨” 회귀 테스트를 추가한다.

### CR-02 — HWPX 치환은 새 CLI 수준이며 Excel 연계·한컴/PDF 완료 조건을 충족하지 못함

**파일:** `scripts/hwpx_token_fill.ps1:15-16,29-32,126-160`, `scripts/verify_hwpx_token_fill.ps1:7-8,60-79`, `test.md:66,83`

**근거:** 새 `hwpx_token_fill.ps1`은 HWPX 사본의 허용된 공통 토큰을 채우는 CLI이지만, 주석대로 Excel VBA에서 호출하지 않으며(15-16행), Excel 기초자료→Form ID별 템플릿 선택→출력이라는 사용자 흐름이 없다. 회귀 검증도 F-007 한 종의 인위적 토큰화만 다루고(verify 7-8, 29-61행), Kordoc SVG 렌더까지만 수행한다(75-79행). 한컴 열기와 PDF 비교는 여전히 자동/수동 완료 증빙이 없고, `{{교장명}}`은 개인정보 경계상 명시적으로 거부된다(29-32행). `test.md`의 H-05는 `NOT_RUN`, X-06은 `FAIL`이다.

**영향:** HWPX 출력은 현재 XLSM의 선택 출력과 연결되지 않으며, F-007 외 템플릿의 반복행·토큰·A4/PDF·한컴 호환성이 증명되지 않았다. HWPX 출력 가능 또는 P3 완료로 선언할 수 없다.

**수정:** (1) Form ID별 허용 필드 매핑과 토큰/라벨 규약을 확정하고, (2) Excel 기초자료에서 비식별 허용값만 추출해 HWPX 사본에 적용하고, (3) fill → validate → 재열기 → 한컴/PDF 비교를 한 명령에서 기록하도록 구현한다. 교장명 자동 반영은 개인정보 경계에 대한 별도 사용자/업무 승인 없이는 허용 목록에 넣지 않는다. Kordoc 제약으로 `{{...}}`가 불가한 기존 템플릿은 UI·문서에 명시하고, 웹 전환 ADR과 최소 웹 구현의 개인정보·삭제·다운로드 검증을 선행한다.

## Major

### MA-01 — PDF/A4 검증이 실제 조판 검증이 아니라 페이지 나눔·파일 크기 검사에 머묾

**파일:** `scripts/verify_excel_v1.ps1:124-141,632-684`

**근거:** A4 판정은 현재 PC/프린터 설정에 의존하는 `HPageBreaks`, `VPageBreaks`, `Zoom`만 본다. PDF는 선택된 모든 서식을 한 번에 내보낸 뒤 최신 PDF의 파일 크기만 0보다 큰지 확인한다. PDF 페이지 수, Form ID별 페이지 범위, 텍스트 누락, 잘림, 병합표·결재란 조판은 자동 검사하지 않는다.

**영향:** 파일이 생성되기만 하면 잘린 PDF, 잘못된 페이지 수 또는 특정 서식의 레이아웃 실패가 PASS가 될 수 있다. 사용자 요구인 “한글 A4와 동일 크기”의 재현성 증빙도 부족하다.

**수정:** Form ID별 개별 PDF를 생성하고, PDF 메타데이터의 페이지 수와 A4 MediaBox를 검사한다. 렌더 이미지/SVG의 기준선 비교 또는 문서별 육안 승인 기록을 필수 게이트로 분리한다. 프린터 드라이버 의존 조건도 고정하거나 검증 환경에 기록한다.

### MA-02 — 품질 훅이 30초 제한에서 전체 Excel 검증을 매 편집마다 병렬 실행해 신뢰할 수 없음

**파일:** `.claude/settings.json:3-46`, `.claude/hooks/verify-phase.ps1:366-395`, `scripts/verify_excel_v1.ps1:16-34,708-724`

**근거:** `PostToolUse`의 모든 Write/Edit에 30초짜리 훅이 등록되어 있고, 이 훅은 Excel COM·PDF 내보내기까지 수행하는 전체 검증기를 다시 실행한다. 검증기는 시작 시 로그·검증 디렉터리를 재귀 삭제하고 종료 시에도 삭제한다. 동시 훅 실행에는 상호 배제(lock)가 없으며, 프로젝트 로그에도 이 경합이 반복 기록되어 있다. `.git/hooks`에는 샘플만 있고 Git pre-commit/pre-push 훅은 없다.

**영향:** 훅의 시간 초과·경합·로그 삭제 때문에 실제 PASS/FAIL 증빙이 비결정적이며, Codex 외에서 실행하거나 커밋할 때는 품질 게이트가 강제되지 않는다.

**수정:** 가벼운 정적 검사(파서·PSScriptAnalyzer·`git diff --check`)와 긴 Excel/PDF 통합 검증을 분리한다. 통합 검증에는 단일 인스턴스 락과 실행별 고유 로그/임시 경로를 사용하고, CI 또는 실제 Git pre-commit/pre-push에서 재현 가능한 명령을 호출한다.

### MA-03 — PDF/미리보기 예외 시 임시 업체별 시트가 정리되지 않음

**파일:** `scripts/build_excel_v1_vba.ps1:1473-1582,1584-1620`

**근거:** F-015~F-025 출력은 임시 시트를 만든 뒤, `PrintPreview` 또는 `ExportAsFixedFormat`이 성공한 다음에만 `F015임시시트정리`를 호출한다. 오류 처리나 `Finally`가 없어서 프린터/PDF 엔진 오류, 사용자의 미리보기 오류, 파일 잠금 시 정리 코드에 도달하지 못한다.

**영향:** 복사된 업체명/평가값을 담은 시트가 통합문서에 남고, 사용자가 저장하면 원치 않는 데이터 보존·재출력 및 다음 출력의 이름 충돌 위험이 생긴다.

**수정:** 임시 시트 이름을 생성 즉시 추적하고 `On Error GoTo Cleanup` 단일 종료 경로에서 항상 삭제한다. PDF/미리보기 오류를 사용자에게 보고한 뒤에도 `DisplayAlerts` 상태와 활성 시트를 복원한다. Export 실패 회귀 테스트에서 임시 시트 0건을 검증한다.

### MA-04 — 개인정보성 값이 ‘업체명’ 필드로 우회 저장될 수 있음

**파일:** `scripts/build_excel_v1_vba.ps1:241-265,804-845`; `scripts/verify_excel_v1.ps1:553-558`

**근거:** 업체 검증은 특정 단어, 8자리 이상 숫자, 몇 가지 전화번호 패턴만 막는다. 예를 들어 `홍길동`처럼 레이블·숫자 없이 입력된 개인 성명은 2~150자 조건을 통과하고 DB_업체로 저장된다. 테스트도 `대표자 홍길동` 등 레이블이 붙은 우회만 검사한다.

**영향:** 프로젝트의 개인식별정보 입력·저장 금지 경계가 자동으로 보장되지 않으며, 실수로 개인명이 DB/PDF에 남을 수 있다.

**수정:** 업체명에 개인명을 허용하지 않는 정책이면 공인 업체명 목록/승인된 사업자 원본과 대조하도록 입력 경계를 바꾸고, 대조 불가 환경에서는 자동 차단을 주장하지 말고 저장 전 명시적 확인 및 PDF 전 개인정보 점검을 강제한다. 순수 개인명·공백/구두점 변형·한글 연락처 변형을 포함한 음성 테스트를 추가한다.

### MA-05 — HWPX 실패 시 요청한 출력 경로에 부분 변경 파일이 남을 수 있음

**파일:** `scripts/hwpx_token_fill.ps1:126-147`

**근거:** 템플릿을 최종 `OutputPath`에 즉시 복사한 다음 그 파일을 Update 모드로 열어 section XML을 하나씩 삭제·재생성한다. 이후 section 처리나 최종 재열기 검증이 실패해도 출력 파일은 삭제·격리되지 않는다.

**영향:** 호출자가 오류 종료 코드를 놓치거나 후속 자동화가 파일 존재만 확인하면 토큰 일부만 바뀐 HWPX를 정상 결과로 사용하게 된다.

**수정:** 같은 볼륨의 고유 임시 파일에 복사·수정·재열기 검증을 마친 뒤에만 원자적 이동으로 `OutputPath`를 교체한다. 실패 시 임시 파일을 제거하고 기존 출력본을 보존한다. 중간 section에서 의도적으로 실패시키는 회귀 테스트를 추가한다.

### MA-06 — HWPX 회귀 검증이 이동하는 `kordoc@^4` 패키지에 의존함

**파일:** `scripts/verify_hwpx_token_fill.ps1:18,75-79`

**근거:** 검증은 `npx -y kordoc@^4`로 실행할 때마다 네트워크에서 호환 범위의 최신 버전을 내려받는다. lockfile, 정확한 버전, 해시 또는 설치 경로가 없다.

**영향:** 같은 소스·템플릿이라도 실행 시점에 따라 렌더/검증 결과가 바뀌고, 오프라인·제한 환경에서는 품질 게이트가 재현되지 않는다.

**수정:** 검증된 정확한 Kordoc 버전과 런타임을 프로젝트에 고정하고, 설치/버전 확인을 사전 단계로 분리한다. 결과 기록에 CLI 버전과 한컴 버전을 함께 남긴다.

## Minor

### MI-01 — 레거시 MVP 실행기가 `Invoke-Expression`을 사용하고 품질 게이트의 린트 대상에서도 빠짐

**파일:** `scripts/run_excel_mvp_utf8.ps1:1-6`, `.claude/hooks/verify-phase.ps1:337-361`

**근거:** PSScriptAnalyzer가 `PSAvoidUsingInvokeExpression`을 보고했다. 훅의 린트 목록은 최신 빌드 3개와 훅 자신만 포함해 이 실행기는 검사하지 않는다. 이 명령은 현재 안전 빌드가 아닌 초기 MVP 초안을 생성한다.

**수정:** 파일 내용을 평가하지 말고 안전 빌드와 같은 `& ([scriptblock]::Create(...))` 또는 명시적 `powershell -File` 호출로 교체한다. 사용하지 않는 초기 MVP 경로는 사용자 문서에서 제거하거나 실행 시 중단 메시지를 내고, 모든 `scripts/*.ps1`을 린트 범위에 포함한다.

### MI-02 — HWPX 재현 스크립트가 필수 Automation 실패를 삼키고 예외 시 한컴 프로세스를 정리하지 않음

**파일:** `_workspace/02_hwpx/P2-01/repro/make_automation_min.ps1:4-10,21-24`, `_workspace/02_hwpx/P2-01/repro/make_automation_multi.ps1:4-9,26-29`

**근거:** `RegisterModule`·`SetMessageBoxMode` 실패를 빈 `catch`로 무시하며 `try/finally`가 없어 Insert/SaveAs 실패 시 `Clear`·`Quit`가 실행되지 않는다. PSScriptAnalyzer도 네 개의 빈 `catch`를 보고했다.

**수정:** 성공/실패를 로그에 남기고 파일 접근 모듈 등록 실패는 즉시 중단한다. HWP 객체의 `Quit`·COM 해제는 `finally`로 옮긴다. 이 실험 스크립트는 제품 경로와 분리해 산출물 생성에 사용하지 않는다.

### MI-03 — 새 HWPX 스크립트도 품질 훅의 린트 대상이 아님

**파일:** `.claude/hooks/verify-phase.ps1:337-361`, `scripts/hwpx_token_fill.ps1:70,111`, `scripts/verify_hwpx_token_fill.ps1:18`

**근거:** 현재 훅의 PSScriptAnalyzer 대상은 기존 Excel 빌더·검증기와 훅뿐이다. 새 파일은 독립 실행에서 승인되지 않은 동사, 자동 변수 `Args` 재정의, UTF-8 BOM 규칙 위반을 보고했지만 현재 훅은 이를 잡지 못한다.

**수정:** 모든 제품 `scripts/*.ps1`을 린트 목록에 포함하고, `Args`를 `KordocArgs`로 바꾸며 파일 인코딩 정책을 빌드 실행 방식과 일치시킨다.
