## 6. 매크로 동작 — 직접 실행 재현 (부분 통과, 재현 못한 항목 있음)

VBA 컴포넌트 10개(문서모듈 8: `현재_통합_문서`+`Sheet1~7`, 표준모듈 2: `Module_기초자료`/`Module_출력`) 존재를 직접 확인함. `Module_기초자료`/`Module_출력` 소스 전문을 직접 읽어 로직을 검토하고, 아래와 같이 직접 실행함:

| 매크로 | 에이전트 검증 이력 | 내 직접 재현 결과 |
|---|---|---|
| `저장하기()` | 실행함(로그 확인) | **직접 재현 성공**: 마스킹 테스트값("QA테스트초등학교" 등) 입력 후 실행 → DB 2행에 정상 기록(H1=1, DB!B2=QA테스트초등학교) 확인. 테스트 후 DB 행 삭제로 정리함. 파일은 저장하지 않고 닫아 배포본 변경 없음(재검증 후 크기·수정시각 동일 확인). |
| `초기화()` | 실행함(로그 확인) | **직접 재현 성공**: 실행 후 기초자료입력 C4가 빈 문자열로 정상 초기화됨을 확인. |
| `선택서식_PDF저장()` | 실행함(로그 확인) | 에이전트 로그의 PDF 파일을 직접 열어 페이지 수(2쪽)를 독립 검증함(3절 참고). 내가 별도로 재실행하지는 않음(동일 결과가 파일로 이미 남아 있어 중복 실행 불필요로 판단). |
| `수정하기()` | **실행 이력 없음** — `verify_excel_v1.ps1`에 테스트 코드 자체가 없음 | 소스 코드 검토로 `저장하기()`와 동일한 필드 매핑 패턴(`필드복사_기초자료_DB` 공용 함수 재사용)임을 확인함. 헤드리스 자동 실행은 이번 회차에 시도하지 않음(아래 비고). |
| `불러오기()` | **실행 이력 없음** | 소스 코드 검토로 로직은 확인함(DB 행 조회 후 C4~C25 역매핑, 역방향도 `저장하기()`와 컬럼 순서 일치). **직접 실행 시도했으나 실패**: `InputBox` 모달이 무인 헤드리스 자동화(`Application.Visible=False`+`SendKeys` 큐잉)에서 안정적으로 응답받지 못해 Excel 프로세스가 응답 없음 상태에 빠짐. 프로세스를 강제 종료해 회수했고, 종료 후 대상 파일의 크기·수정시각이 종료 전과 동일함을 확인해 **파일 손상·변경은 없었음**을 확인함. |

> 필드 매핑 정합성은 별도로 수식 단위까지 추적함(7절 참고) — `저장하기()`의 DB 컬럼 순서와 `수정하기()`/`불러오기()`의 컬럼 순서가 동일하므로, 코드 검토 수준에서는 로직 결함을 발견하지 못했음. 다만 **실제 실행 재현은 "저장하기"와 "초기화" 2종만 성공**했고, "수정하기"·"불러오기"는 실사용자 환경(대화상자를 보고 직접 [확인]을 누르는 환경)에서의 수동 확인이 남아 있음(9절 "남은 수동 확인 항목" 참고). 이는 Critical/High로 분류하지 않음 — 코드가 `저장하기()`와 동일 패턴을 그대로 재사용하는 저위험 로직이기 때문임.

## 7. 필드 매핑 정합성 — 수식 단위 추적 (통과, 최초 의심 해소)

기초자료입력 시트의 라벨(A/B열)과 F-007/F-024/DB 저장 매크로가 참조하는 셀 주소가 실제로 대응하는지 전수 대조함. 예: F-007의 "3. 기초금액" 표시행(C14 수식)은 `기초자료입력!C15`(라벨 "기초금액(원)", B-04)를 참조하고, "4. 계약방식" 표시행(C15 수식)은 `기초자료입력!C14`(라벨 "계약방식", B-03)를 참조함 — 행 번호는 어긋나지만(C14↔C15 교차 참조) **라벨-값 대응은 정확함**(F-007의 표시 순서와 기초자료입력의 입력 순서가 의도적으로 다르게 설계됨). DB 저장 매크로의 컬럼 순서(`필드복사_기초자료_DB`)도 DB 헤더 순서와 1:1로 정확히 일치함. F-024의 K-01(금액=수량×단가)은 `기초자료입력!E29:E38`에 `=IF(AND(B29<>"",C29<>"",D29<>""),C29*D29,"")` 수식으로 실제 구현되어 있고, K-02(합계)는 `=SUM(E29:E38)`로 구현됨 — **둘 다 정상 작동**을 직접 확인함.
