## 2. 차단 사유

Kordoc의 `fill`은 동일 라벨을 문서 전체에서 함께 치환할 수 있음. 현재 원본은 여러 서식을 포함한 복합 매뉴얼이므로, Form ID별 독립 사본·고유 토큰을 만들지 않은 채 마스킹 시험값을 채우면 다른 서식의 같은 표식까지 변경할 위험이 있음.

따라서 현재 파일만으로 F-007·F-024·F-013 각각의 치환·저장·재열기 POC를 안전하게 수행할 수 없음. 원본을 전역 치환하거나 실제 계약·개인정보 값을 넣는 방식은 수행하지 않음.

## 3. 재개 방식 및 완료 조건

사용자 지시에 따라 다음 방식을 적용해 P2-01을 재개했으나, 실제 치환 단계에서 차단됨.

1. 원본 복합 매뉴얼은 수정하지 않고, F-007·F-024·F-013별 독립 HWPX 작업 사본을 `artifacts/hwpx/P2-01/`에 생성함.
2. 모든 자동 입력 위치에는 `{{F007_학교명}}`처럼 Form ID 접두어를 포함한 고유 토큰을 사용함. 같은 값이 여러 위치에 필요하면 동일 토큰을 반복하지 않고 위치 식별자를 덧붙임.
3. 반복표는 행별 토큰과 최대 행 수를 명세하며, 공통 라벨을 이용한 복합 매뉴얼 전역 치환은 수행하지 않음.
4. 가상 학교명·가상 품목·마스킹 역할표시만 포함한 JSON으로 `fill -j`를 수행함. `validate`와 렌더는 통과했으나, F-007 템플릿은 최소 JSON에서도 “문서 처리 중 오류”로 실패해 이후 치환·재열기·한컴 수동 열기와 PDF 비교를 중단함.

독립 템플릿·고유 토큰의 명세와 결과는 `_workspace/02_hwpx/P2-01/독립템플릿_토큰명세_검증.md`에 기록함. 원본 조판을 보존한 독립 분리와 한컴 수동 확인은 아직 검증 전이므로 P2-01을 완료 처리하지 않음.
