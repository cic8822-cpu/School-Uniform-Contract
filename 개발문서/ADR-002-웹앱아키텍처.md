# ADR-002 — 웹앱(P5) 아키텍처 결정

- **상태**: DONE(확정) — 2026-09-25 개정판. 사용자가 직접 제공한 상세 스펙(0-2 화면구성계획, 0-1 개발 프롬프트, 화면 디자인 PDF 6장)을 최종 근거로 채택
- **작성일**: 2026-09-25 (1차) → 2026-09-25 개정(같은 날, §7)
- **관련 Phase**: P5-01(계획.md), `웹앱_prd.md` 전체
- **선행 결정**: `ADR-001-HWPX출력방식.md`(Excel 로컬 경로 — 계속 유효, 웹과 양립)

## 1. 배경 및 개정 경위

1차 작성(같은 날) 당시에는 시안 이미지 일부(`첫화면/원앙/`)만 근거로 "웹은 HWPX를 생성하지 않고 Excel 경로만 안내"·"9단계 절차 허브를 첫 화면"으로 결정했었다. 이후 사용자가 다음 3개 문서를 직접 제공하며 이 결정을 뒤집었다:

- `첫화면\교복 학교주관구매 웹앱 화면 디자인.pdf` — 실제 클릭 가능한 고해상도 화면 6종(디자인시스템/홈/계약절차/기초자료입력/서식함/문서미리보기)
- `0-2.교복 학교주관구매 웹앱 — 화면 구성 및 디자인 계획.md` — IA·데이터모델·화면설계·디자인시스템 전체 명세
- `0-1.교복계약 웹앱개발-프롬프트.txt` — 매뉴얼을 Source of Truth로 하는 구현 원칙·데이터 구조·검증 기준

이 세 문서가 `웹앱_prd.md`·`웹앱_계획.md`·`웹앱_trd.md`의 확정 근거이며, 이 ADR은 그 중 아키텍처 수준 결정만 요약한다.

## 2. 결정 (1차에서 뒤집힌 항목)

| 항목 | 1차 결정(철회) | **최종 결정** | 근거 |
|---|---|---|---|
| HWPX 생성 | 웹은 생성하지 않고 Excel 안내만 | **웹에서 직접 생성함.** 단 HTML을 `.hwpx`로 위장 저장하는 방식 금지 — 원본 HWPX 템플릿을 보존하고 `{{필드}}`만 치환하는 방식(표/문단/글꼴/정렬/쪽설정/머리말·꼬리말 유지) | `0-1.txt` §15, `0-2.md` §7-1 |
| 첫 화면 IA | 9단계 구매절차 허브 | **계약방법 4종 선택 카드**(1인견적수의계약·2인견적수의계약·2단계계약·일반입찰계약)가 홈의 핵심. 9단계 절차 허브는 폐기(Excel도 동일하게 이미 전환함) | `0-2.md` §5, PDF p.2 |
| 실행 방식 | HWPX 생성을 서버리스로 미룸 | **클라이언트 사이드(브라우저) 생성** — 서버는 여전히 두지 않음. `hwpx_token_fill.ps1`의 핵심 로직(zip 해제→`hp:t` 텍스트 노드의 `{{토큰}}` regex 치환→재압축)은 Windows 전용 API에 의존하지 않아 JSZip+DOMParser로 브라우저 포팅이 기술적으로 가능함을 조사로 확인(2026-09-25 Explore 조사) | 본 세션 기술 조사 |

**변경되지 않은 것(유지)**: 서버·DB 완전 미사용, 학교 업무자료 서버 미전송·미저장, 정적 배포, Excel Import/Export(업무자료.xlsx) 지원, 계약방법 자동판정 금지(사용자가 직접 선택).

## 3. 확정 아키텍처

```
[정적 웹앱 — Static-first. HTML/CSS/JS 또는 React/Vite로 빌드하되 최종 산출물은 정적 파일만]

홈(계약방법 4종 카드 선택, 자동판정 없음)
  └─ 계약절차(선택 계약방법의 Stepper: 1인견적4/2인견적5/2단계·일반입찰 각 11단계)
       └─ 단계 상세(해야 할 일·주의사항·필요 기초자료·관련 서식 표)
            └─ 서식함 카드 / 문서 미리보기 모달
                 ├─ 기초자료입력(7개 탭, Single Source of Truth) — 직접 입력 또는 Excel 업로드(클라이언트 파싱)
                 ├─ 미리보기(A4, 원본 레이아웃 최대 보존)
                 ├─ PDF 저장(클라이언트 렌더링, page-break/margin/표/폰트 제어)
                 ├─ HWPX 작성(클라이언트 사이드: JSZip으로 원본 템플릿 zip 해제 → {{필드}} 치환 → 재압축 → 다운로드)
                 └─ 내보내기(업무자료.xlsx 다운로드, 선택 서식 일괄 PDF/HWPX ZIP)

[별도 배포: 교복구매 길라잡이 Excel XLSM — 로컬 사용, 웹앱과 독립적으로 계속 운영]
```

배포 방식: **학교 PC 로컬 설치 패키지**. GitHub Pages·Vercel 등 외부 호스팅은 사용하지 않음(2026-09-25 사용자 확정).

### 3.1 서버가 필요 없는 이유
- 계약방법·Workflow·Form·Field Master는 빌드 시점 정적 JSON(`/data/contract-methods.json` 등)으로 충분.
- 기초자료는 브라우저 세션에만 존재, 필요 시 Excel로 내려받아 학교가 직접 보관(서버 미경유가 곧 개인정보 보호 경계).
- PDF/HWPX 모두 "정적 템플릿 + 값 치환"이라 클라이언트 처리로 충분.

## 4. 리스크 및 한계 (정직하게 기록)

- `hwpx_token_fill.ps1`의 허용 토큰 목록(`$AllowedTokens`)·금지 패턴(`$ForbiddenTokenPattern`)을 TypeScript로 포팅할 때 원본과 완전히 일치시켜야 함 — 어긋나면 개인정보 경계가 깨짐. `quality-compliance-reviewer`가 이 일치 여부를 별도 검증함.
- F-013(교복 디자인 및 규격서)은 표·이미지 복합조판이라 웹에서도 "HWPX 우선(복합조판)" 상태로 유지하고 완전 자동화하지 않음(Excel과 동일한 예외, `0-2.md` 서식함 카드 예시에서도 확인됨).
- `kordoc validate` 같은 구조 검증 CLI는 브라우저에서 실행 불가 — 대신 재압축 후 즉시 재파싱해 `{{...}}` 잔존 여부를 클라이언트에서 자체 검증(PowerShell 스크립트의 기존 안전장치와 동등한 수준).
