# 교복 학교주관구매 웹앱 — 화면 구성 및 디자인 계획

Sep 25, 2026 · @최익창

전북특별자치도교육청 「교복 학교주관구매 계약방법 안내 및 서식자동화 웹앱」의 화면 구성(IA)과 디자인 계획입니다. 첨부된 업무 매뉴얼(HWPX)을 업무·서식의 원본 기준으로, 기존 Excel 자동화 파일(v17)의 데이터 구조를 웹앱 데이터 모델 기준으로 사용했습니다.

## 1. 개요 및 설계 원칙

이 웹앱의 목적은 서식 다운로드 사이트가 아니라 **계약방법 확인 → 전체 절차 이해 → 현재 단계 확인 → 서식 확인 → 기초자료 입력 → 서식 자동작성 → 미리보기 → PDF/HWPX 출력**까지 한 화면 흐름으로 처리하는 "교복 학교주관구매 디지털 업무 길라잡이"입니다.

**핵심 원칙**

1. Source of Truth 이원화 — 업무 절차·계약조건·서식 원문은 첨부 매뉴얼(「교복 학교주관구매 운영 요령」, 2026.9)을 그대로 따르고, 화면 구조·필드·자동화 관계는 기존 Excel 자동화 파일(교복구매\_길라잡이\_20260924\_v17.xlsm)의 구조를 그대로 승계합니다. 매뉴얼에 없는 절차를 임의로 추가하지 않으며, 원본 서식 문구를 UX 편의로 요약해 실제 출력물에 쓰지 않습니다.
2. 매뉴얼 원본 번호 보존 — 매뉴얼의 \[9-7\], \[서식 2\] 같은 표기는 삭제·변경하지 않고, 시스템 Form ID(F-001\~F-052)와 병기합니다(예: "F-019 · 매뉴얼 \[9-7\]·\[서식 2\] · 입찰참가신청서").
3. 계약방법은 사용자가 선택 — 시스템이 추정금액으로 계약방법을 자동 판정하지 않습니다(Excel 「계약방법안내」 시트와 동일한 원칙). 판단에 도움이 되는 정보만 제공합니다.
4. 정적 웹앱 · 서버 DB 미사용 — 입력한 업무자료는 브라우저 세션에만 존재하며 서버에 저장하지 않습니다. Excel 업로드/다운로드로 학교가 직접 보관합니다.
5. 초보자·숙련자 동시 지원 — 처음 담당자는 단계별 안내(Workflow)를 따라가고, 숙련자는 서식 검색·최근 사용 서식으로 바로 이동합니다.
6. 불확실한 사항은 화면과 데이터 모두에 "매뉴얼 확인 필요" 상태로 명시합니다.

## 2. Information Architecture

메인 네비게이션 7개로 구성하고, 모든 화면이 하단 넘기기없이(모달/드로워 대신) 플랻하게 연결되도록 설계합니다.

| 메뉴 | 역할 | 주요 페이지 |
| --- | --- | --- |
| 홈 | 진입점, 전체 진행률 요약, 계약방법 카드 진입 | 홈 대시보드 |
| 계약방법 안내 | 4개 계약방법 비교·선택 | 계약방법 카드 4종 |
| 계약절차 | 선택한 계약방법의 전체 Workflow, 단계별 상세 | Stepper + 단계 상세 |
| 기초자료 | 공통·사업·문서별·반복 입력값 관리(Single Source of Truth) | 7개 입력 섹션 |
| 서식함 | 전체 52종 서식 검색·필터·상태확인 | 검색/필터 결과 카드 |
| 내보내기 | Excel 업무자료.xlsx 내려받기, 이력 내보내기 | 내보내기 패널 |
| 사용안내 | 첫 사용자 온보딩, 개인정보 안내, FAQ | 온보딩 3단계 |

**사용자 시나리오 2가지**

- **초보 담당자(주력 페르소나)**: 홈 → 계약방법 안내에서 조건 비교 후 선택 → 계약절차 Stepper를 처음부터 따라감 → 각 단계에서 "해야 할 일/필요서식/미작성 기초자료"를 확인하며 진행.
- **숙련 담당자**: 상단 검색바 또는 서식함에서 바로 해당 Form ID로 이동 → 기초자료가 이미 채워져 있으면 즉시 미리보기/PDF/HWPX 출력.

Global UI에는 항상 현재 위치(Breadcrumb), 기초자료 입력 완성도 배지, 상단 검색창을 고정 배치해 눈 액션이 어디서든 다른 화면으로 이동할 수 있도록 합니다.

## 3. 데이터 모델

Excel 자동화 파일의 「기초자료입력」 시트에 이미 Canonical Field Dictionary가 정의되어 있어, 이를 그대로 웹앱의 기초자료 필드 체계로 사용합니다.

**3-1. 기초자료 필드 그룹**

| 그룹 | 코드 | 내용 |
| --- | --- | --- |
| 공통정보 | C-01\~C-08 | 학교명, 학년도, 담당부서, 담당자 직위/성명, 문서 발행일, 문서번호, 교장 성명(결재권자) — 학교명 입력 시 주소/전화는 학교검색 DB에서 자동 채움 |
| 사업정보 | B-01\~B-07 | 구매명, 구매학년, 계약방식, 기초금액, 예정수량, 납품기한, 제출기한 |
| 문서별정보 | D-01\~D-05 | 수신, 제목, 관련문서, 붙임목록, 안내문 본문 — 서식 공통 기본값 |
| 품목 반복행 | R-04\~R-06, K-01 | 품목명, 수량, 단가, 금액(자동계산) |
| 업체 반복행 | R-03, R-08, R-09 | 업체명, 대표자 성명, 대표자 연락처 |
| 위원 반복행 | R-01, R-02 | 역할·직위, 위원 성명(마스킹 표시 원칙 적용) |
| 평가점수 반복행 | R-07, K-03 | 평가항목, 배점, 점수, 총점(자동계산) |

같은 값을 여러 번 입력하지 않도록 이 필드를 **Canonical Field**로 삼아 전체 52종 서식이 공유하며(예: `{{SCHOOL_NAME}}`→C-01, `{{BASIC_PRICE}}`→B-04, `{{COMPANY_NAME}}`→R-03), 학교명을 한 번 변경하면 이를 사용하는 모든 서식에 즉시 반영됩니다.

**3-2. Form Master 요약(업무단계별)**

Excel 「서식선택\_출력」 시트에 전체 52종 Form ID(F-001\~F-052)가 이미 매핑되어 있습니다. 구현상태는 Y(구현가능) / D(HWPX 우선순위 위임 — 표·이미지 복합조판) / N(미구현)으로 표시합니다.

| 업무단계 | Form ID 범위 | 서식 수 | 대표 서식(예) | 미구현(N) |
| --- | --- | --- | --- | --- |
| 1. 준비 | F-001\~F-006 | 6 | 위원회구성기안, 구매추진계획, 운영위원회심의안 | — |
| 2. 입찰(구매요청\~제출서류) | F-007\~F-013, F-017\~F-031 | 22 | 구매요청, 교복사양서, 기초금액계약방법결정, 입찰공고, 계약특수조건, 입찰참가신청서 등 | F-026, F-028 |
| 3. 평가 | F-014\~F-016, F-032\~F-040 | 12 | 평가항목배점기준, 정량·정성평가, 제안서접수결과, 업체별제안서평가표 | — |
| 4. 계약 | F-041\~F-043 | 3 | 낙찰자결정, 낙찰자결정통보, 계약체결 | — |
| 5. 구매안내·사후평가 | F-044\~F-052 | 9 | 가정통신문 2종, 수요조사 2종, 만족도조사 4종 | F-051, F-052 |

> 전체 52종의 System ID · 매뉴얼번호 · 작성주체(학교/업체/공동) 상세 매핑은 별도 Form Master 시트로 관리하며, 서식함 화면의 카드 메타데이터로 노출됩니다.

## 4. 계약방법 4종과 표준 업무 워크플로우

매뉴얼은 2단계 입찰(규격·가격 동시)을 주된 예시로 상세히 다루며, 지방계약법 시행령 제18조에 근거해 1인·2인견적 수의계약과 일반입찰도 함께 존재합니다. 기존 참고 Figma 시안에서도 4개 계약방법 카드로 구분되어 있어 이 구조를 그대로 계승합니다.

| 계약방법 | 적용 조건(참고) | 단계 수 | 공통 필수 서식 | 전용 핵심 서식 |
| --- | --- | --- | --- | --- |
| 1인견적 수의계약 | 추정가격이 소액인 경우(매뉴얼 확인 필요 — 금액 기준은 지방계약법을 따름) | 4 | F-008 교복사양서, F-012 계약특수조건 | — |
| 2인견적 수의계약 | 2개 이상 업체 비교견적이 필요한 경우 | 5 | F-008, F-012 | — |
| 2단계 계약(규격·가격 동시) | 품질 적격심사 후 가격경쟁(지방계약법 시행령 제18조③) | 11 | F-008\~F-012 + 제안·평가 서식 일체 | F-009 기초금액계약방법결정, F-010 사전규격공개 |
| 일반입찰계약 | 공개경쟁이 원칙인 경우 | 11 | 2단계계약과 동일한 서식 체계 | — |

**표준 9단계 업무 흐름**(Excel 「입찰계약절차안내」 기준, 2단계/일반입찰 계약 기준. 수의계약은 이 중 주요 단계만 축약 적용)

```mermaid
flowchart LR
  A[1.준비<br/>위원회구성] --> B[2.심의<br/>운영위원회]
  B --> C[3.구매요청<br/>기초조사]
  C --> D[4.입찰공고<br/>규격·특수조건]
  D --> E[5.제안·접수<br/>참가신청]
  E --> F[6.평가<br/>정량·정성]
  F --> G[7.낙찰<br/>결정·통보]
  G --> H[8.계약·납품<br/>계약체결]
  H --> I[9.구매안내·사후평가]
```

각 단계는 관련 Form ID 범위와 "대표 이동 Form ID"를 가지며(Excel 「입찰계약절차안내」 시트), 계약절차 화면의 Stepper 데이터로 그대로 사용됩니다.

## 5. 화면 설계 1 — 홈 / 계약방법 안내

**5-1. 홈**

상단에 전북특별자치도교육청 로고 + "교복 학교주관구매 길라잡이"(H1) + "계약방법 안내부터 서식 작성·출력까지 한 곳에서"(부제). 그 아래 노란 배너("한눈에 보는 계약 업무 길라잡이" GO 버튼)로 3분 온보딩으로 진입할 수 있게 합니다.

하단은 "계약 방식을 선택해 주세요" 4장의 계약방법 카드(STEP 1\~4)를 가로 배치합니다. 카드당 표시 요소: 계약방법명, 한줄 설명, 적용조건 문구, 단계 수 배지(예: "4단계"), 필요서식 수, \[절차 확인 →\] 버튼. 카드 상단 액센트 바로 계약방법별 색(틸/코랄/보라/블루)로 구분합니다. 카드 클릭 시 계약방법을 시스템이 확정하지 않고, 계약절차 화면으로 이동하는 "확인용" 액션입니다(원칙 3 참조).

상단 우측에는 유틸리티 내비게이션(\[기초자료입력으로\] \[서식선택\_출력으로\])를 배치해 숙련자가 바로 이동할 수 있게 합니다(기존 Excel UX 계승).

**5-2. 계약방법 안내**

4종 카드를 다시 한번 더 자세히 비교하는 페이지로, 매뉴얼 기준 적용조건·주요절차·필요서식수를 표(4열)로 비교하고, 각 행 끝에 \[이 방식으로 진행\] 버튼을 둔니다. 상단에는 "계약방법은 행정실 담당자가 근거 법령과 추정금액을 검토하여 최종 결정합니다"라는 안내 문구로 자동판정이 아니임을 명시합니다(원칙 3).

## 6. 화면 설계 2 — 계약절차 / 기초자료입력 / 서식함

**6-1. 계약절차(Workflow)**

Desktop 2단 레이아웃: LEFT에 수직 Stepper(단계번호+단계명, 현재 단계 강조), RIGHT에 선택 단계의 상세 카드. 기존 참고시안("계약 절차 안내" 모달)을 전체 화면으로 확장한 구조입니다. RIGHT 카드 구성 요소:

- 단계명 + 한줄 설명(업무설명)
- 담당 구분 배지(학교 / 업체 / 공동)
- "해야 할 일" 체크리스트
- "주의사항" 안내 박스(매뉴얼 근거 문구 그대로 인용)
- 필요 기초자료 상태(입력됨/미입력 배지)
- 관련 서식 테이블: \[코드\]\[서식명\]\[작성상태\]\[미리보기\]\[PDF\]\[HWPX\]
- 하단 액션: \[이전 단계\] \[다음 단계\]

예시(2단계계약, 11단계): STEP01 입찰공고문작성 → STEP02 지정정보처리장치공고 → … → STEP11 변경계약. 단계명/순서는 반드시 매뉴얼 분석 결과를 따릅니다(원칙 2).

**6-2. 기초자료입력**

좌측 탭(공통/사업/문서별/품목/업체/위원/평가) + 우측 폼(선택한 탭의 입력 기로와 "저장하기"). 상단에 Privacy 안내 배너를 고정 노출: "입력한 업무자료는 서버 DB에 저장하지 않습니다…". 우측 사이드패널에는 "서식선택\_출력과 실시간 연동"되는 빠른 출력 체크리스트를 배치(Excel 구조 계승). 품목/업체/위원/평가는 반복행 테이블 UI(+ 행 추가/삭제)로 구현하고, 학교명 입력 시 학교검색 모달(790개 학교 DB)을 호출해 자동완성합니다. 가운데 상단에 Excel 업로드 / 다운로드(업무자료.xlsx) 버튼을 둔니다.

**6-3. 서식함**

상단 검색창(서식명/번호) + 필터 칩(전체/준비/기초금액/입찰/제안/평가/계약/납품/검사·검수/대가지급/가정통신문/기타). 서식 카드에 System Form ID, 매뉴얼 원본번호, 서식명, 사용 계약방법 배지, 사용 업무단계, 작성주체(학교작성/업체작성/학교·업체공동/참고자료) 배지를 표시. 작성 가능 상태는 ● 작성가능(녹) / ▲ 기초자료 필요(주황)로 배지하고, ▲ 클릭 시 단순히 "작성할 수 없습니다"가 아니라 누락된 입력값 목록 + \[기초자료 입력하기\] 버튼을 인라인 카드로 하단에 펼칩니다(원칙 12).

## 7. 화면 설계 3 — 문서 미리보기 / 내보내기 / 사용안내

**7-1. 문서 미리보기(Document Workspace)**

서식 카드 클릭 시 Large Modal로 전환. CENTER에 A4 문서 미리보기(원본 매뉴얼 레이아웃을 최대한 유지 — 표/단락/정렬/머리말·꼬리말 보존), RIGHT에 서식 정보 패널(필수입력값 리스트, 자동반영된 데이터 미리보기, 누락 데이터 경고). 하단 고정 액션바: \[미리보기\] \[PDF 저장\] \[HWPX 작성\] \[닫기\] — 기존 참고 시안의 버튼 배치와 동일합니다.

HWPX 작성은 원본 HWPX 템플릿의 Field만 치환하는 방식(표/문단/글꿀/정렬/쪽설정 유지)이며, PDF는 동일 데이터로 A4 기준 page-break·margin·표·글꿀을 제어해 공문서 레이아웃이 무너지지 않도록 합니다(원칙 15\~16). 기술적으로 구현되지 않은 기능은 버튼 자체를 노출하지 않습니다.

**7-2. 내보내기**

"현재 입력된 전체 기초자료를 업무자료.xlsx로 다운로드"와 "선택한 서식 일괄 출력(PDF/HWPX 묶음 ZIP)"을 제공합니다. 상단에 Privacy 안내문을 다시 한 번 고정 노출합니다.

**7-3. 사용안내**

첫 방문자를 위한 3단계 가이드(계약방식 선택 → 기초자료 입력·저장 → 서식 작성·출력), FAQ(서버 저장 여부, 오프라인 사용 가능 여부 등), 용어집(계약방식·서식안내 용어)를 포함합니다.

## 8. 디자인 시스템

기존 참고 시안(전북특별자치도교육청 브랜드, "모두가 빛나게 다함께 새롭게")을 그대로 계승하여 Korean Public Education Administrative SaaS 톤(Professional / Trustworthy / Clean / Accessible)을 유지합니다.

**컬러**

| 용도 | 색상 | HEX(참고) |
| --- | --- | --- |
| Primary | Jeonbuk Deep Navy | #1B2A5B |
| Secondary 1 | Education Blue | #2E5AAC |
| Secondary 2 | Teal(1인견적) | #14B8A6 |
| Secondary 3 | Coral/Orange(2인견적) | #F0653E |
| Secondary 4 | Purple(2단계계약) | #6D5BD0 |
| Secondary 5 | Blue(일반입찰) | #2F6FED |
| Background | White / Light Gray | #FFFFFF, #F7F8FA |
| Accent(브랜드) | 오렌지 | #F5A623 |

계약방법별 Accent는 카드 상단바·버튼·Stepper 활성 색에만 제한적으로 사용하고, 본문·배경은 네이비/화이트로 통일합니다.

**타이포그래피**: 본문 폰트는 Pretendard 또는 Noto Sans KR. H1 28\~32px/Bold, H2 22\~24px/Semibold, H3 18px/Semibold, Body 15\~16px/Regular, Caption 13px/Regular. A4 문서 미리보기는 공문서 관례상 바탕체/굴림체 계열 유지.

**컴포넌트**

- 카드(계약방법, 서식): 모서리 둥근 12px, 상단 액센트 바 4px, 그림자 최소화
- Stepper: 좌측 수직형, 완료(✓)/현재(채움 원)/예정(빈 원) 3가지 상태
- 상태 배지: ● 작성가능(Teal/녹), ▲ 기초자료 필요(오렌지/주황), ○ 미구현(회색)
- 버튼: Primary(Navy 채움), Secondary(아웃라인), Ghost(텍스트링크)
- 정보 배너: 연한 파란배경 + 아이콘으로 Privacy/주의사항 안내

**지양하는 요소**(매뉴얼 지침 원칙 17 반영): 과도한 gradient, glassmorphism, 애니메이션, 진한 그림자, 장식적 일러스트레이션.

모든 컴포넌트는 WCAG 2.1 AA 대비(텍스트 최소 대비 4.5:1) 기준으로 설계하여, 고령층을 포함한 공공기관 사용자가 문제없이 읽을 수 있도록 합니다.
