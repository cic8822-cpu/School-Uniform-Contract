작성일: 2026-09-15 · 대상: 전주교육지원청 교복 학교주관구매 자동화 플랫폼 기획

## 0. 결론 먼저 (So What 미리보기)

**이미 검증된 국내 패턴 위에서 시작할 수 있다.** 전북(추정) 교육청 내부에는 "입력시트 1개 → 서식시트 자동반영(셀 참조) → 체크박스 선택출력" 구조의 VBA 엑셀 자동화 템플릿(용역계약갈라잡이)이 이미 존재하고, 서울교육청은 교복구매를 포함한 전 계약분야를 웹 플랫폼(contract.sen.go.kr)으로 서비스하며 "서식 원클릭" 다운로드까지 제공 중이다. [AI] 반면 부산교육청은 교복구매 절차를 웹에 "안내"만 하고 서식 자동생성 기능은 없다. [AI] 즉 **엑셀 자동화 로직은 재사용 가능한 국내 선례가 있고, 웹 플랫폼화는 서울이 유일한 완성 사례이자 우리가 참고·차별화할 벤치마크**라는 것이 이번 리서치의 핵심 결론이다.

### 1-2. 「용역계약갈라잡이(디깅모멘텀)」(xlsm) — 기존 자동화 아키텍처 분석

이 파일은 **이미 검증된 국내(추정 전북교육청 소관) 계약서식 자동화 엑셀의 실물 사례**로, 구조를 그대로 벤치마킹할 수 있다.

**시트 구성**

| 시트명 | 역할 |
|---|---|
| Sheet1 | 계약분야(물품/용역/공사)·유형·추정가격 선택 메인 화면 |
| 기본정보 입력하기 | **단일 입력시트** — 발주기관 정보, 계약업체 정보, 용역 기초자료(금액·일정 등)를 한 번만 입력 |
| 계약서식 | 표준계약서 등 각 서식이 세로로 연속 배치(약 700행), 모든 셀이 `='기본정보 입력하기'!G13` 식으로 입력시트를 참조 |
| DB, Ref_data, 학교정보, Rtable_용역/A/Property | 코드표·드롭다운 목록·학교 마스터 데이터 |
| Print_sheet | 선택된 서식만 모아 인쇄용으로 재구성 |

**핵심 자동화 로직 (VBA + 수식)**

1. 입력시트 우측에 서식별 **체크박스(0/1 값)** 열(AG·AH열)이 있어, 사용자가 원하는 서식만 선택
2. 체크박스 값에 따라 `=IF(AG12=1,"A1:BD33,","")` 형태의 수식이 **인쇄할 셀 범위 문자열을 자동으로 조합**
3. 매크로(`서식출력` 등)가 조합된 범위 문자열을 읽어 해당 구간만 복사/인쇄 또는 별도 시트로 전송
4. `Workbook_Open()` 이벤트에서 페이지 나누기(HPageBreak)를 서식 구간별로 자동 세팅 — 서식 단위 인쇄 분리
5. `소속기관검색폼`: 학교명을 입력하면 지역·유형·주소를 자동 완성해 채워주는 검색 팝업(사용자 요청하신 "학교정보 자동입력 팝업"과 정확히 같은 기능이 이미 구현되어 있음)
6. 리본 메뉴(Module1)에 "계약의 이해", "계약 절차", "관련 법령", G2B·S2B·나라장터·법제처 바로가기 버튼이 있어 **매뉴얼+서식+외부링크가 한 화면에 통합**되어 있음

흥미로운 점은, 코드 내부(Sheet3.cls)에 `IntDrop_2 = "3"`일 때 `UserForm_popup_교복_사전절차.Show`를 호출하는 분기가 이미 존재한다는 것이다. 즉 **이 템플릿 계열(물품 유형 버전)에는 이미 "교복" 전용 사전절차 팝업이 설계되어 있(었)을 가능성이 높다.** 다만 이번 첨부파일(용역 버전)에는 해당 UserForm 모듈 자체는 포함되어 있지 않아 코드만 남아있는 상태다. {{"물품" 계열의 자매 파일(교복/우유급식/조달 등 사전절차 폼 포함 버전)이 조직 내에 존재하는지 원본 소장처에 확인 필요}} — 만약 존재한다면 이번 작업의 시간을 크게 단축시킬 수 있다.

**시사점**: 사용자께서 구상하신 "기초자료 1회 입력 → 서식 자동반영 → 체크박스 선택출력 → hwpx/PDF 출력" 흐름은 전북교육청 계열에서 이미 실전 검증된 패턴이며, 교복 버전은 이 구조를 그대로 복제하되 (a) 계약서식뿐 아니라 가정통신문·설문지·평가표까지 범위를 넓히고 (b) 입력항목을 교복 특화 항목(디자인, 원단, 상한가격, 선정위원회 명단 등)으로 교체하면 된다.

**차별화 포인트 정리**

- 서울은 이미 "정보 제공 + 서식 자동화 + 법령/지침 아카이브"를 모두 갖춘 완성형 웹 플랫폼이라, 이를 그대로 벤치마킹하면 **정보구조(IA)** 설계 시간을 크게 아낄 수 있다. [AI]
- 다만 서울 사이트는 게시판형 CMS(자료실 다운로드 중심)이며, 사용자가 원하시는 "절차 클릭 → 팝업 입력 → 즉시 hwpx/PDF 출력"과 같은 **입력→생성형 UX는 아닌 것으로 보인다.** [AI] 이 지점이 본 프로젝트가 서울보다 한 단계 더 나아갈 수 있는 차별화 포인트다.
- 부산은 정보 제공에 그쳐 우리 프로젝트의 벤치마크로는 낮은 우선순위다.
- {{서울 "서식 원클릭" zip 내부가 실제로 엑셀 자동화(VBA) 방식인지, 단순 서식 모음(빈 양식)인지는 로그인/다운로드로 직접 확인이 필요}} — 이는 다음 단계에서 실제 파일을 내려받아 구조를 대조해보는 것을 권장한다.

## 4. 웹앱 기술 스택 비교 (2단계 — 참고용)

이미 프로젝트 메모에 **B안(중앙 HTML 웹앱·Stateless·단일 URL·완전 오픈형)**으로 방향이 확정되어 있으므로, 이 전제를 기준으로 비교한다.

| 옵션 | Stateless 단일 URL과의 적합성 | 학교 담당자 접근성 | 관리 난이도(본인 기준) | 비용 | 비고 |
|---|---|---|---|---|---|
| 정적 HTML/JS (Netlify·GitHub Pages 등) + 브라우저 내 hwpx/PDF 생성 | 매우 높음 — 서버·DB 불필요, URL 하나로 완결 | 높음(링크 클릭만 하면 됨, 로그인 불필요) | 낮음(코드 수정 후 재배포만 하면 됨) | 무료~매우 저렴 | 사용자가 확정하신 "학교 자료를 서버에 저장할 필요 없음"과 가장 정합적 |
| Supabase(백엔드+DB) | 낮음 — DB에 저장한다는 것은 Stateless 전제와 상충 | 중간 | 중간(테이블·인증 설계 필요) | 무료 티어 존재하나 사용량 증가 시 과금 | 여러 학교의 입력값을 서버에 누적 저장·통계화하려는 요구가 생기면 그때 도입 검토 |
| Google Apps Script 웹앱 | 높음(URL 하나로 배포 가능) | 중간(구글 팝업 인증·속도 이슈로 체감 느릴 수 있음) | 낮음(스프레드시트 친화적) | 무료 | 프로젝트 메모의 "구글앱스크립트 또는 HTML 웹앱" 초기 구상과 일치 |

**결론**: 현재 확정하신 요구사항(서버 저장 불필요, 완전 오픈형, 단일 URL)만 보면 **Supabase 같은 백엔드 DB는 당장 불필요**하다. hwpx/PDF 생성도 브라우저 내(클라이언트 사이드)에서 처리하면 서버가 전혀 필요 없다. Supabase는 "학교별 진행상황을 중앙에서 취합·통계 내고 싶다"는 요구가 나중에 생길 때 도입해도 늦지 않다. "코덱스"로 표현하신 도구가 정확히 어떤 서비스를 지칭하시는지는 확인이 필요하다. {{"코덱스 사이트"가 의미하는 구체 서비스명 확인 필요}}

## So What — 그래서 우리는 뭘 해야 하는가

1. **엑셀 1단계 설계에 즉시 반영**: `용역계약갈라잡이.xlsm`의 "입력시트 1개 + 체크박스 선택 + 자동 페이지브레이크 + 학교정보 검색팝업" 구조를 교복 버전 설계의 기준 골격으로 채택한다. 처음부터 새로 설계하지 말고 이 구조를 복제·확장하는 방식이 가장 빠르다.
2. **서식 인벤토리부터 확정**: 다음 대화에서 hwpx 3~5·7~8단계 구간을 함께 표 단위로 재검토해, "텍스트로 그대로 옮길 서식"과 "이미지·표라 재입력이 필요한 서식"을 구분한 최종 서식 목록(개수 포함)을 확정한다.
3. **웹앱은 서버 없는 정적 HTML로 1차 방향 설정**: 이미 확정하신 Stateless·완전오픈형 요구와 가장 잘 맞으며, Supabase는 "여러 학교 데이터를 중앙에서 취합하고 싶다"는 요구가 실제로 생길 때 2단계로 검토한다.
4. **서울 "서식 원클릭" 실물을 1회 확보해 대조**: 직접 다운로드해 내부가 엑셀 매크로인지 확인하면, 우리 엑셀 설계에 바로 참고할 실물 사례가 하나 더 생긴다.
5. **grill-me 방식 PRD 착수 전 확정해야 할 질문 3가지**
   - 엑셀에서 hwpx로 "그대로" 내보낼 때 한글/한컴 문서 서식(표 테두리, 로고 배치 등)을 어느 수준까지 재현해야 하는지
   - 57개(추정) 서식 전부를 1차 릴리즈에 포함할지, 사용 빈도가 높은 상위 서식(선정위원회 구성, 입찰공고, 계약체결, 가정통신문 2종, 만족도조사)부터 단계적으로 출시할지
   - 웹앱에서 "완전 오픈형" 접속 시 학교별 데이터(기관명·서명 등)를 매번 새로 입력하게 할지, 브라우저 로컬 저장(localStorage 유사 방식은 배제 대상이므로 실제로는 URL 파라미터·다운로드한 입력파일 재업로드 방식 등)으로 재입력 부담을 줄일지

이 사항들을 기존 프로젝트 메모(uniform-purchase-automation)의 다음 대화에서 `grill-me` 스킬로 순서대로 질문·확정하시면, 바로 prd.md·계획.md 작성으로 넘어갈 수 있는 상태입니다.
