### 2.2 VBA 분석 경계

`vbaProject.bin`의 존재는 확인했으나, 이 환경에서는 VBA 프로젝트 객체 모델의 신뢰 액세스를 자동으로 활성화하지 않았고 독립 OLE/VBA 분석 도구도 실행 경로에서 확인되지 않았음. 따라서 모듈·프로시저 원문과 호출 지점은 아직 미분류 상태임.

이는 VBA 이식을 금지하고 필요한 기능만 신규로 설계한다는 결론에는 영향을 주지 않음. 다만 신규 매크로 범위를 확정하기 전, 업무담당자가 원본의 실제 사용 버튼·출력 절차를 시연하거나 신뢰 액세스가 허용된 격리 환경에서 모듈 역할만 추가 분류해야 함.

## 5. 신규 XLSM 최소 설계 기준

1. `01_교복구매_워크플로우`, `02_기초자료_입력`, `03_서식선택_출력`, Form ID별 서식, `DB`, `Ref_data`, `학교정보`, `서식Metadata`, `사용설명서`를 분리함.
2. 공통값·문서 전용값·반복행·계산값을 테이블 또는 명확한 입력 범위로 분리함.
3. 외부 링크, 외부 연결, `#REF!` 이름 정의는 각각 0건을 완료 조건으로 둠.
4. VBA는 입력값 초기화·선택 인쇄 등 필요성이 승인된 최소 기능만 제공하고 Microsoft 365에서 검증함.
5. 인쇄영역·용지·여백·머리글·바닥글·페이지 나눔은 서식별 골든 PDF와 비교함.

## 6. 한계 및 후속 검증

- OOXML 정적 분석은 VBA 코드의 실제 동작, Excel 수식 재계산 결과, 인쇄물의 시각적 레이아웃을 보장하지 않음.
- 업무 셀 원문·계약 정보·연락처는 분석 기록에 저장하지 않았음.
- P1 데이터 모델 확정 후, 새 XLSM 사본에서 새 이름정의·연결·링크 검사와 Microsoft 365 수동 인쇄/PDF 검증을 수행해야 함.
