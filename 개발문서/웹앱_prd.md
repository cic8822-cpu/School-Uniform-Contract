# 웹앱 PRD — 교복 학교주관구매 길라잡이 웹

- **상태**: `DRAFT — 사용자 제공 상세 스펙 반영(2026-09-25 전면 개정)`
- **작성일**: 2026-09-25 (1차) / 2026-09-25 개정
- **근거(Source of Truth)**: `0-1.교복계약 웹앱개발-프롬프트.txt`(구현 원칙), `0-2.교복 학교주관구매 웹앱 — 화면 구성 및 디자인 계획.md`(IA·데이터모델·화면설계), `첫화면\교복 학교주관구매 웹앱 화면 디자인.pdf`(화면 6종 시안), `ADR-001-HWPX출력방식.md`, `ADR-002-웹앱아키텍처.md`
- **범위**: Excel MVP와 별개로 운영되는 웹앱(P5) 전용 PRD. Excel 요구사항은 루트 `prd.md`를 따름.

## 1. 문제와 목표

학교 업무담당자(특히 처음 담당하는 직원)가 교복 학교주관구매의 계약방법을 확인하고, 전체 절차를 이해하고, 현재 단계에 필요한 서식을 찾아 기초자료를 한 번만 입력해 자동 작성·출력(PDF/HWPX)까지 끝낼 수 있는 **"교복 학교주관구매 디지털 업무 길라잡이"**를 만든다. 단순 서식 다운로드 사이트가 아니라 **계약방법 확인 → 전체 절차 이해 → 현재 단계 확인 → 서식 확인 → 기초자료 입력 → 서식 자동작성 → 미리보기 → PDF/HWPX 출력**을 한 화면 흐름으로 제공한다(`0-2.md` §1).

**Source of Truth 이원화**(`0-1.txt` §1, 최우선 원칙): 업무절차·계약조건·서식 원문은 교복 매뉴얼 HWPX를 그대로 따르고(임의 추가·요약 금지), 기초자료 구조·Form ID·자동화 관계는 기존 Excel 자동화 파일(`교복구매_길라잡이_20260924_v17.xlsm`)의 구조를 승계한다. 매뉴얼 원본 번호(`[9-7]`, `[서식 2]` 등)는 삭제·변경하지 않고 시스템 Form ID(F-001~F-052)와 병기한다.

## 2. 사용자와 시나리오

| 페르소나 | 시나리오 |
|---|---|
| 초보 담당자(주력) | 홈 → 계약방법 카드 비교 후 선택 → 계약절차 Stepper를 처음부터 따라감 → 각 단계에서 "해야 할 일/필요서식/미작성 기초자료" 확인하며 진행 |
| 숙련 담당자 | 상단 검색바 또는 서식함에서 바로 해당 Form ID로 이동 → 기초자료가 이미 채워져 있으면 즉시 미리보기/PDF/HWPX 출력 |

## 3. Information Architecture (메인 네비게이션 7개)

| 메뉴 | 역할 |
|---|---|
| 홈 | 진입점, 계약방법 4종 카드 선택(시스템 자동판정 없음) |
| 계약방법 안내 | 4종 비교(적용조건·절차·필요서식수) |
| 계약절차 | 선택 계약방법의 Stepper + 단계별 상세 |
| 기초자료 | 7개 섹션 입력(공통/사업/문서별/품목/업체/위원/평가), Single Source of Truth |
| 서식함 | 전체 52종 서식 검색·필터·상태확인 |
| 내보내기 | 업무자료.xlsx 다운로드, 선택 서식 일괄 PDF/HWPX |
| 사용안내 | 온보딩 3단계, FAQ, 용어집 |

Global UI: 현재 위치(Breadcrumb), 기초자료 입력 완성도 배지, 상단 검색창을 항상 고정 배치.

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 | 검증 기준 |
|---|---|---|---|
| WFR-01 | 홈에서 계약방법 4종(1인견적수의계약/2인견적수의계약/2단계계약/일반입찰계약)을 카드로 제시하며, 시스템이 금액 등으로 자동판정하지 않고 사용자가 직접 선택함 | P0 | 카드 클릭은 "확인용 이동"일 뿐 계약방식을 확정하지 않음. "계약방법은 담당자가 직접 선택합니다" 문구 노출 |
| WFR-02 | 선택한 계약방법의 전체 절차를 Stepper(좌)+단계 상세(우)로 보여줌(1인견적 4단계/2인견적 5단계/2단계·일반입찰 각 11단계) | P0 | 단계명·순서는 반드시 매뉴얼 분석 결과를 따름(임의 추가 금지) |

## 5. 데이터 모델 (요약 — 상세는 `웹앱_trd.md`)

- **계약방법 Master**: 계약방법/적용조건/업무단계/관련서식
- **Workflow Master**: 계약방법/Step/단계명/업무설명/관련서식
- **Form Master**: System ID/매뉴얼번호/서식명/업무단계/작성주체/사용 계약방법/필요 Field/출력방식 — 전체 52종
- **Field Master**: Field ID/한글명/Type/Required/사용 서식/Source — `입력데이터_사전.md`의 C/B/D/R/K 필드 체계를 그대로 사용
- **Template Mapping**: 원본문구/Field ID/자동치환 여부

이 4+1 Master가 완성되기 전에는 UI 코드를 임의로 작성하지 않는다(`0-1.txt` §3, §22 — 코딩 전 필수 선행 조건).

## 6. 비기능 요구사항

- **학교 PC 로컬 설치**: 정적 파일만 학교 PC에 배포(Static-first). React/Vite 등으로 빌드하더라도 최종 산출물은 외부 호스팅 없이 실행되는 정적 파일.
- **개인정보 미전송**: 입력값·엑셀 파싱 결과 모두 서버로 전송하지 않음.
- **HWPX/PDF 클라이언트 생성**: 둘 다 브라우저에서만 실행(`ADR-002`).
- **원본 보존**: 매뉴얼 서식 문구·법적 표현을 임의로 새로 작성하거나 UX 편의로 요약해 실제 출력물에 쓰지 않음. 불확실한 사항은 "매뉴얼 확인 필요"로 명시.
- **경로 하드코딩 금지**: 특정 개발 PC의 절대경로(`C:\Users\...`)를 코드에 포함하지 않음.
- **접근성**: WCAG 2.1 AA.

## 7. 수용 기준 (`0-1.txt` §24 최종 검증 시나리오 기반)

신규 학교 담당자가 처음 접속 → 계약방법 확인 → 계약방법 선택 → 전체 절차 확인 → STEP 선택 → 관련 서식 확인 → 기초자료 입력 → 서식 자동반영 확인 → 미리보기 → PDF 출력 → HWPX 작성 → Excel 업무자료 백업까지 끊김 없이 완료되어야 하며, 다음을 모두 만족해야 한다:

1. 매뉴얼의 전체 업무단계·전체 서식이 반영됨
2. 원본 매뉴얼 번호가 보존됨(Form ID와 병기)
3. 서식과 업무단계가 정확히 연결됨
4. 공통 입력값이 중복 입력되지 않음(Canonical Field 동작)
5. 반복 데이터(품목/업체/위원/평가)가 정상 동작함
6. 원본 서식 내용이 임의 변경되지 않음
7. PDF 출력이 정상이고 레이아웃이 무너지지 않음
8. HWPX 원본 레이아웃이 유지됨
9. 서버에 학교 업무자료를 저장하지 않음
10. 인터넷 없이도 핵심 기능을 사용할 수 있음

## 8. 범위 제외

학생별 주문·치수·설문 데이터 수집·저장, 직인·서명 자동 처리, 계약방법 자동판정(사용자가 직접 선택), 서버 저장·이력 관리·로그인/권한 체계, 실시간 협업. F-013(교복 디자인 및 규격서)처럼 표·이미지 복합조판 서식은 완전 자동화 대상에서 제외하고 "HWPX 우선(복합조판)" 상태로 표시함(Excel과 동일 원칙).
