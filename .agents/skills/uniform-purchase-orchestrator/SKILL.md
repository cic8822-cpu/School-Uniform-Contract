# 교복구매 길라잡이 오케스트레이터

## 실행 모드

**하이브리드**: 독립적인 원본 분석은 병렬 하위 에이전트로 수행하고, 문서 자동화 → Excel 구현 → 품질 검증은 선행 산출물을 넘기는 파이프라인으로 실행함.

## 팀 구성

| 에이전트 | 역할 | 호출 시점 |
|---|---|---|
| `uniform-workflow-analyst` | 매뉴얼·서식 인벤토리·업무 흐름 분석 | P0~P1 |
| `document-automation-engineer` | Kordoc POC, HWPX 템플릿·출력 연계 | P0·P2 |
| `excel-automation-engineer` | XLSM 워크플로우·입력·서식·출력 구현 | P0·P3 |
| `quality-compliance-reviewer` | 회귀·출력·보안·배포 검토 | 각 산출물 완료 전 |

## 실행 절차

1. [계획.md](../../../계획.md)를 읽어 `IN_PROGRESS`와 가장 높은 우선순위의 `TODO`를 확인함.
2. `_workspace/`가 없으면 `00_input`, `01_analysis`, `02_hwpx`, `03_excel`, `04_qa`를 생성함. 재개 작업에서는 기존 기록을 읽고 필요한 부분만 보완함.
3. 원본 HWPX·XLSM은 읽기 전용으로 취급하고 사본·산출물은 `artifacts/`에 생성함.
4. P0~P1에서는 서식 분석과 XLSM 의존성 분석을 병렬화하되, 각각의 근거 파일을 남김.
5. P2 HWPX POC는 대표 3종의 템플릿화·치환·재열기·PDF 비교·한컴 확인이 모두 통과해야 다음 단계로 진행함.
6. P3 Excel 구현은 확정된 서식 인벤토리와 매핑표를 사용하며 외부 링크·연결·`#REF!` 이름 정의를 새 파일에 만들지 않음.
7. 각 단위 완료 전 `quality-compliance-reviewer`가 골든 테스트, 입력 오류, PDF/HWPX 출력 및 데이터 노출 여부를 검토함.
8. 검토 통과 후에만 [계획.md](../../../계획.md), `로그.md`, `test.md`, `체크리스트.md` 상태를 갱신함. 불통과 항목은 `BLOCKED`로 남기고 다음 독립 작업을 진행함.

## 데이터 전달 규칙

- 중간 산출물: `_workspace/{단계}_{역할}_{산출물}.md`
- 최종 산출물: 루트 문서 또는 `artifacts/excel`, `artifacts/hwpx`, `artifacts/pdf`
- 문서 데이터, 연락처, 계약금액은 Git·로그·대화에 원문으로 기록하지 않으며 필요한 경우 마스킹함.
- Form ID, 원본 위치, 입력 필드, 출력 검증 결과를 모든 전달 문서에 포함함.

## 오류 및 중단 처리

- HWPX 기술검증 실패: Excel/PDF 범위는 유지하되 HWPX 자동생성은 `BLOCKED`로 격리함.
- 서식 개수 불일치: 인벤토리 근거를 우선하고 57종 목표와 차이를 보고함.
- 매크로·외부 연결 오류: 기존 XLSM을 복제하지 않고 새 XLSM에 최소 기능으로 재구현함.
- Critical/High 품질 결함: 완료로 선언하지 않고 수정·재검증함.

## 테스트 시나리오

- 정상 학교 1개, 필수값 누락 1개, 최대 길이/특수문자 1개, 복수 업체·위원 1개를 골든 테스트로 유지함.
- 원본 서식과 생성본의 필드·표·결재란·체크박스·페이지 수·PDF 잘림을 Form ID별로 확인함.
- 생성 문서는 행정실 직원이 사실관계·계약조건·서식 상태를 최종 확인한 뒤 출력함.
