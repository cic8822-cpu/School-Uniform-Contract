먼저 밝혀 둘 한계 — Mobbin 스크린샷은 이 보고서에 없습니다. 요청하신 Mobbin MCP는 검색할 때마다 “유료 플랜 필요” 오류를 반환해 화면을 하나도 받지 못했습니다. 잠긴 콘텐츠를 크롤링으로 우회하지 않았고, 대신 로그인 없이 누구나 볼 수 있는 공개 페이지를 직접 열어 캡처했습니다. 아래 “레퍼런스” 화면은 모두 Mobbin이 아닌 GOV.UK 디자인 시스템·GOV.UK 서비스 페이지·KRDS(대한민국 정부 디자인 시스템)이며, 각 캡션에 URL을 적었습니다. Mobbin 유료 플랜 전환 시 같은 형식으로 화면을 추가할 수 있습니다.

PART 3무엇을 고려해서 만들어야 하나

적용 가능바로 옮길 수 있는 점

  1. 계약절차에 진행 표시기를 붙인다. 완료·현재·남은 단계를 구분하고 연결선으로 순서를 보여준다.근거: 화면 R3-②, R4-②③④ · 앱 화면 B-①
  2. 기초자료입력 탭마다 상태 태그를 둔다. 공통·사업·문서별·품목·업체·위원·평가 각각 “완료 / 미완료”.근거: R1-①②④ · 앱 화면 C-③
  3. 내보내기 앞에 “입력 내용 확인” 화면을 넣는다. 항목·값·[수정] 링크를 묶음별로 나열하고, 마지막에 동작 이름이 분명한 버튼을 둔다.근거: R2-①~④ · 앱 화면 E-③
  4. 입력 힌트의 수식 원문을 사람이 읽는 문장으로 바꾼다. public/data/fields.json 149행·1223행의 validation 값을 “2000~2100” 형태로.근거: 앱 화면 C-④ (파일에서 직접 확인) · KRDS 입력 폼 가이드(입력 단위·도움말 근접 배치)
  5. 버튼 위계를 통일한다. 주 버튼 1개는 진하게, 나머지는 같은 스타일의 보조 버튼으로. “엑셀에서 불러오기”, “ZIP으로 내려받기”가 브라우저 기본 모양이다.근거: 앱 화면 C-②, E-③ · KRDS 입력 폼 가이드(액션 버튼 일관성)
  6. “해야 할 일”이 위 설명문과 똑같은 문장을 반복하지 않게 한다. 행동 단위 목록으로 쪼갠다.근거: 앱 화면 B-②
  7. 서식함 카드는 위쪽 기준으로 정렬한다. 제목 줄 수가 달라도 유형·상태 줄이 같은 높이에 오게.근거: 앱 화면 D-②

검증 필요적용 전에 더 확인할 점

  1. 11단계를 7단계 이하로 묶어도 되는가. KRDS는 단계 표시기를 3~7개로 권장하는데, 2단계 계약·일반입찰은 11단계다. 매뉴얼 근거로 묶음이 타당한지 확인해야 한다.출처: KRDS 단계 표시기 사용성 가이드라인 · 앱 홈 카드(11단계)
  2. 임시 저장을 어떻게 할 것인가. 이 앱은 “서버에 저장하지 않는다”는 원칙이다. 소스(webapp/src) 검색에서 localStorage·sessionStorage 사용 흔적을 찾지 못해, 새로고침 시 입력이 유지되는지 실측이 필요하다. 브라우저 저장을 넣는다면 공용 PC의 개인정보 노출 위험과 함께 판단해야 한다.출처: KRDS 신청 서비스 패턴(임시 저장 항목) · 앱 기초자료입력 안내문
  3. 모바일·좁은 화면. 이번 캡처는 데스크톱(1709px)뿐이다. 창 크기를 줄인 실측은 되지 않아 결과를 판단하지 않았다.
  4. 접근성. 색 대비, 키보드 이동, 스크린리더 읽기 순서는 측정하지 않았다. 앱에 “본문으로 바로가기” 링크와 라벨 있는 nav가 있음을 확인했을 뿐이다.
  5. 홈의 주황 “GO” 배너 문구. “한눈에 보는 계약 업무 길잡이”가 어디로 가는지 화면만으로 알기 어렵다. 실제 사용자가 무엇을 기대하는지는 사용자 관찰이 필요하다.
  6. 영어권 사례를 한국 현장에 그대로 가져와도 되는가. GOV.UK는 작은 질문을 한 화면씩 묻는 방식이 많다. 이 앱의 사용자는 숙련된 행정실 담당자이고, KRDS도 “숙련된 사용자에게 단계별 입력은 효율적이지 않다”고 적고 있다. 화면 분할 여부는 현장 의견이 필요하다.
  7. Mobbin 실제 출시 앱 화면. 이 보고서에는 없다. 유료 플랜 전환 후 온보딩·서류 작성·체크리스트 앱 사례를 추가 조사하면 비교 폭이 넓어진다.

이미지 이용: 레퍼런스 스크린샷은 내부 분석용으로 캡처했습니다. GOV.UK 콘텐츠는 Open Government Licence v3.0 범위에서 재사용할 수 있고, KRDS는 사이트의 저작권정책 확인 후 외부 배포하세요. 현재 앱 화면의 입력란은 비어 있으며 실제 개인정보를 포함하지 않습니다.

“관찰” 항목은 캡처 화면과 fields.json에서 직접 확인한 내용입니다. 그 외 제안은 위 근거 화면에서 도출한 판단이며, 현장 검증 전에는 확정이 아닙니다.
